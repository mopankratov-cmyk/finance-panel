# Внедрение финансовых изменений

## 1. Принять изменения через Pull Request

1. Открыть:
   `https://130.193.34.46/pankman100/finance-panel/compare/main...fix/bank-import-forecast`
2. Если браузер предупреждает о сертификате, выбрать:
   **Дополнительно → Продолжить переход на 130.193.34.46**.
3. Проверить направление слияния:
   - база: `main`;
   - ветка изменений: `fix/bank-import-forecast`.
4. Создать Pull Request.
5. Дождаться проверки AI-gate.
6. Если проверка потребует ручного решения, проверить изменения и нажать Merge.

Ветка включает автоматическое распознавание банковских выписок, предварительную
проверку операций, защиту от повторной загрузки, исправления платёжного календаря,
распознавание PDF-выписок и выгрузку финансовых реестров в исходные шаблоны.

## 2. Обновить Google Apps Script

Эта часть не устанавливается на сервер автоматически после Merge.

1. Открыть целевую Google Таблицу.
2. Выбрать **Расширения → Apps Script**.
3. Открыть файл `Code.gs`.
4. Полностью заменить его содержимое кодом из:
   `app/api/opiu/google-sheets/GoogleAppsScript.gs`.
5. Сохранить проект.
6. Открыть **Развернуть → Управление развертываниями**.
7. Нажать значок редактирования активного веб-приложения.
8. В поле версии выбрать **Новая версия**.
9. Нажать **Развернуть**.

Если новую версию не выпустить, Google продолжит выполнять старый код.

## 3. Применить миграцию идемпотентности

После Merge выполнить в Supabase SQL Editor файл:

`supabase/migrations/20260727_finance_bank_import_idempotency.sql`.

Миграция создаёт защищённую серверную очередь банковских операций, сопоставления
банковских счетов и уникальный ключ импорта платежа. Без неё очередь проверки и
защита от одновременного подтверждения в двух вкладках не будут работать.

## 4. Проверить листы-шаблоны

В целевой Google Таблице должны заранее присутствовать исходные оформленные листы:

- `ДДС месяц`;
- `Плановый Реестр поступлений`;
- `План выбытий РИО` либо соответствующий лист группы;
- `Факт ДДС`;
- `Учёт кредитов займов от сторонних`.

Скрипт не создаёт упрощённые листы. Он продолжает существующие шаблоны и копирует:

- шрифты, заливки и границы;
- форматы дат и денежных сумм;
- формулы;
- выпадающие списки и проверки данных;
- высоту строк;
- полноценный девятистрочный блок для каждого нового кредита.

Поэтому сначала нужно перенести исходные оформленные листы в целевую Google Таблицу,
если каких-либо из них там ещё нет.

## 5. Проверить настройки сервера

На сервере должны быть заданы:

- `FINANCE_GOOGLE_SHEETS_WEBHOOK_URL` — адрес опубликованного Apps Script;
- `FINANCE_GOOGLE_SHEETS_SECRET` — тот же секрет, который записан в свойствах Apps Script.

В свойствах Apps Script должны быть:

- `FINANCE_SPREADSHEET_ID` — ID целевой Google Таблицы;
- `FINANCE_SYNC_SECRET` — секрет синхронизации.

Секреты нельзя добавлять в Git или вставлять в исходный код.

## 6. Контрольная проверка после внедрения

1. Выгрузить из панели один небольшой период ДДС.
2. Убедиться, что данные появились в продолжении исходной таблицы.
3. Проверить оформление, формулы, даты и денежные форматы.
4. Повторно выгрузить тот же период и убедиться, что дубли не появились.
5. Выгрузить один тестовый кредит и проверить:
   - создание полного оформленного блока;
   - тело кредита;
   - проценты;
   - остаток;
   - включение нового блока в сводные формулы.
