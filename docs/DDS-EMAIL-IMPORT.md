# Автоматический импорт банковских выписок из Gmail

Письма читает n8n. Панель не получает доступ к Gmail: n8n передаёт только
подходящие вложения в два защищённых API-этапа панели. Результат попадает в
очередь «На проверке»; неизвестные компания, счёт или статья не проводятся
автоматически.

## 1. Настройки владельца

1. Создать отдельный Gmail-адрес или ярлык `ДДС/Входящие`.
2. В Vercel создать `DDS_EMAIL_IMPORT_SECRET` для Production, Preview и
   Development. Значение — случайная строка не короче 32 символов.
3. В n8n создать две Credentials:
   - **Gmail OAuth2** для почтового ящика;
   - **Header Auth** с заголовком `Authorization` и значением
     `Bearer <DDS_EMAIL_IMPORT_SECRET>`.

Секрет не вставляется в узел, Code node, описание workflow или репозиторий.

## 2. Workflow n8n

Название: `Import bank statements from Gmail`.

1. **Gmail Trigger — Получить новые выписки**
   - событие: новое письмо;
   - ярлык: `ДДС/Входящие`;
   - вложения: включены;
   - запрос Gmail дополнительно ограничить доверенными отправителями банков.
2. **Извлечь вложения**
   - одна n8n item на одно вложение;
   - binary data не преобразовывать в base64/JSON;
   - пропускать только `.xlsx` и `.pdf`, максимум 20 МБ.
3. **HTTP Request — Распознать выписку**
   - `POST https://finance-panel-two.vercel.app/api/opiu/bank-statement`;
   - Credential: созданный Header Auth;
   - body type: `multipart/form-data`;
   - поле `file`: binary property текущего вложения;
   - retry on fail: 3 попытки, пауза 5 секунд.
4. **HTTP Request — Добавить в очередь**
   - `POST https://finance-panel-two.vercel.app/api/opiu/bank-review`;
   - та же Header Auth Credential;
   - JSON:

```json
{
  "action": "batch",
  "statement": "={{ $json.statement }}",
  "suggestions": "={{ $json.suggestions }}",
  "sourceFileName": "={{ $('Извлечь вложения').item.binary.data.fileName }}"
}
```

5. **Gmail — Пометить обработанным**
   - выполнять только после ответа 2xx второго запроса;
   - убрать ярлык `ДДС/Входящие`, добавить `ДДС/Обработано`.
6. **Error Workflow — Ошибка импорта выписки**
   - добавить ярлык `ДДС/Ошибка`;
   - уведомить ответственного один раз с темой письма, именем файла и текстом
     ошибки; содержимое вложения в уведомление не включать.

Если в одном письме несколько файлов, n8n обрабатывает каждый как отдельную
item. Отдельный Loop Over Items не нужен.

## 3. Защита от дублей

Повтор того же файла отсекается по SHA-256 файла и id строки. Перекрывающиеся
выписки дополнительно сверяются по расчётному счёту, дате, сумме, номеру
документа, счёту/ИНН и имени контрагента. Ответ второго запроса содержит
`duplicatesSkipped` — это штатный результат, а не ошибка.

## 4. Проверка перед включением

1. Отправить на тестовый ярлык одну известную выписку.
2. Сверить число строк и суммы с файлом, проверить банк и кошелёк.
3. Повторно отправить тот же файл: новых строк быть не должно.
4. Отправить выписку с пересекающимся периодом: добавиться должны только новые
   операции.
5. Отправить выписку нового счёта: строки должны остаться «На проверке» до
   присвоения названия кошельку.
6. Только после этих проверок включить боевой Gmail Trigger.
