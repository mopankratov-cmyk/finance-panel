Привет! Ты будешь дорабатывать панель. У тебя есть Claude Code — этого почти достаточно.
Пройди шаги 1–6 один раз (настройка), дальше работай по разделу «Ежедневный цикл».

> Совет: большинство команд ниже можно просто скопировать своему Claude Code и попросить
> «выполни это по порядку, объясни если что-то пошло не так». Но **GitHub-логин (шаг 3)
> и секреты (шаг 5)** сделай по инструкции сам — это доступы.

## Что тебе пришлёт владелец
1. Приглашение в репозиторий на GitHub (придёт на почту / в уведомления GitHub).
2. Ссылку на репозиторий: `https://github.com/mopankratov-cmyk/finance-panel`.
3. Файл `.env.local` с ключами — через защищённую ссылку (1Password / Bitwarden Send), не открытым текстом. (Ещё, опц., приглашение в Vercel как Viewer — чтобы смотреть превью-деплои своих PR.)

  (или письмо «You've been invited…»).

## 2. Установи инструменты
Нужны **Git**, **Node.js 20+** и **GitHub CLI** (`gh`).

**macOS** (через Homebrew — если нет brew, установка: https://brew.sh):
```bash
brew install git node gh
```

**Windows** (через winget в PowerShell):
```powershell
winget install Git.Git OpenJS.NodeJS.LTS GitHub.cli
```

Проверь, что встало:
```bash
git --version && node --version && gh --version
```

## 3. Залогинься в GitHub (доступ к приватному репо)
```bash
gh auth login
```
Выбирай: **GitHub.com → HTTPS → Login with a web browser**. Откроется браузер, подтверди.
Это разом настроит и доступ к репозиторию, и git-логин — отдельные токены/пароли не нужны.

## 4. Склонируй репозиторий
```bash
gh repo clone mopankratov-cmyk/finance-panel
cd finance-panel
```

## 5. Положи ключи (`.env.local`)
Владелец пришлёт ключи безопасно — через 1Password / Bitwarden Send (не открытым текстом). Создай в корне проекта файл `.env.local` и вставь туда присланное содержимое.
- ⚠️ **Никогда не коммить `.env.local`** — он уже в `.gitignore`, оставь так.
- ⚠️ Не пересылай ключи в чаты/почту и не вставляй их прямо в код.
- Доступ в Vercel (если дали) — роль Viewer: только смотреть превью-деплои своих PR; ключи оттуда тянуть не нужно, они уже в `.env.local`.

## 6. Запусти панель
```bash
npm install
npm run dev
```
Открой http://localhost:3000 — панель должна подняться.

## 7. Подтяни командный сетап Claude Code
В репозитории уже лежат общие скиллы, агенты и настройки (режим `acceptEdits`, `.mcp.json`). Разверни скиллы одной командой из корня проекта:
```bash
node scripts/setup-claude.mjs
```
Перезапусти Claude Code — он подхватит ~36 скиллов (SEO/контент/n8n/ui/mpstats и др.), проектного агента `studio-qa` и `.mcp.json`.
- Токены `MPSTATS_TOKEN` / `VIRLO_TOKEN` нужны только если будешь пользоваться теми скиллами/MCP — добавь их в окружение (профиль шелла). Без них всё остальное работает.
- `gstack` (headless-QA, ~1 ГБ) в репо не входит — ставится отдельно, спроси владельца, если понадобится.

Готово, ты настроен.

## Ежедневный цикл (как вносить изменения)

Правило №1: **в `main` напрямую не пишем.** Каждая задача — отдельная ветка и отдельный Pull Request.

1. Обнови `main` и создай ветку под задачу:
   ```bash
   git checkout main && git pull
   git checkout -b feat/коротко-о-задаче     # напр. feat/export-csv или fix/unit-commission
   ```
2. Делай изменения (через Claude Code или руками). Проверяй локально: `npm run dev`.
3. Закоммить и запушь:
   ```bash
   git add -A
   git commit -m "коротко: что сделал"
   git push -u origin HEAD
   ```
4. Открой Pull Request:
   ```bash
   gh pr create --fill
   ```
   Заполни шаблон (что сделал / зачем / как проверить) — это уйдёт владельцу.
5. Дальше работает **AI-гейт**: ИИ-ревьюер смотрит твой PR. Мелкие безопасные правки он одобряет
   и вливает сам (за минуты). Если изменение рискованное (миграции, секреты, зависимости, авторизация,
   оплата, CI, удаление файлов) или ревьюер сомневается — PR уходит владельцу на ручную проверку,
   а чек `ai-gate` будет красным, пока он не вольёт. Это нормально, не пугайся красного.
6. Нужны правки — допиши в той же ветке и снова `git push`. PR и проверка обновятся сами.

## Если фиче нужна новая переменная окружения
Ты **не добавляешь** переменные в Vercel (у тебя доступ Viewer, read-only). Делай так:
1. Локально добавь переменную в свой `.env.local` — чтобы `npm run dev` работал у тебя.
2. Добавь её **имя с заглушкой** в `.env.example` (например `NEW_API_KEY=` или `NEW_API_KEY=your_token_here`) и закоммить — так это попадёт в PR и владелец увидит, что нужна новая переменная.
3. В описании PR явно напиши: «нужна новая переменная `NEW_API_KEY` — что это и где взять значение».

Владелец заведёт реальное значение в Vercel перед мёржем/деплоем. ⚠️ Никогда не вставляй **реальные** ключи в код или в `.env.example` — только в свой локальный `.env.local`.

## Правила (коротко)
- ❌ Не пушить в `main`, не мержить свои PR сам.
- ❌ Не коммитить `.env*`, не вставлять ключи/пароли/токены в код.
- ✅ Одна задача = одна ветка = один PR. Меняй только то, что относится к задаче.
- ✅ Перед PR проверь, что `npm run dev` поднимается без ошибок.
- ⚠️ Миграции БД, удаление файлов, правка оплаты/прод-логики — отметь это явно в описании PR.
- 🆘 Застрял — спроси своего Claude Code или напиши владельцу. Сломать `main` ты не можешь (он защищён) — это нормально, экспериментируй в своей ветке.

> Технические детали проекта Claude Code сам подхватит из `AGENTS.md` / `CLAUDE.md` в корне.
> Этот проект — на **нестандартном Next.js**, поэтому Claude Code сверяется с `node_modules/next/dist/docs/` перед кодом. Не мешай ему это делать.
