# Ключи: доступ через Bitwarden, а не файлом

Раньше владелец присылал `.env.local` разовой ссылкой. Так проще один раз и хуже
дальше: файл устаревает при первой же ротации ключа, лежит копией у каждого, и
чтобы забрать доступ, надо менять все ключи сразу.

Теперь ключи выдаются доступом к хранилищу. Отозвать доступ — одно действие,
ключи менять не нужно.

## Как это устроено

Источник правды — **Bitwarden Secrets Manager**. У проекта `finance-panel` есть
набор `local` с ключами для разработки. Файл `.env.local` не пересылается: он
**генерируется** на машине разработчика из хранилища.

```
Bitwarden Secrets Manager
  └── проект finance-panel
        └── набор local  ──(токен доступа, только чтение)──▶  .env.local (600)
```

## Что делает владелец — один раз на человека

1. Bitwarden → **Secrets Manager** → **Machine accounts** → создать аккаунт,
   например `dev-<имя>`.
2. Дать ему доступ **только к проекту `finance-panel`** и **только на чтение**.
   Ни `content-factory`, ни `rita-studio`, ни прод.
3. Выпустить **access token** и передать разработчику через Bitwarden Send.
   Токен показывается один раз.

Отзыв доступа — удалить machine account. Ключи при этом не меняются: их значения
разработчик никогда не видел иначе как в своём локальном файле.

> **Прод сюда не входит.** Боевые значения живут только в рантайме Vercel и в
> кабинетах провайдеров; из Vercel они не читаются (помечены как sensitive,
> `vercel env pull` возвращает пустые строки). Разработчику прод не нужен и не
> выдаётся.

## Что делает разработчик

Один раз:

```bash
export BWS_ACCESS_TOKEN='<токен от владельца>'
```

Положи это в свой `~/.zshrc` или менеджер окружения — но **не в репозиторий**.

Дальше — сгенерировать `.env.local` из хранилища:

```bash
python3 ~/fleet-secrets/bws_sync.py pull finance-panel/local .env.local
```

Файл создастся с правами `600` и пометкой «не редактировать руками».

Если ключ поменялся — повтори команду, файл перезапишется актуальными значениями.
Руками `.env.local` не правь: следующая генерация затрёт правку, и ты потратишь
час, не понимая почему.

## Проверка

```bash
python3 ~/fleet-secrets/bws_sync.py verify
```

Сверяет хранилище с мастер-файлами по хэшам. **Значения не печатаются** — ни в
выводе, ни в логах.

## Правила, которые не обсуждаются

- `.env.local` не коммитится. Он в `.gitignore` — так и оставь.
- Ключи не пересылаются в чатах, почте и задачах. Только Bitwarden.
- Токен доступа — такой же секрет, как сами ключи. Утёк токен — сообщи сразу,
  его отзовут за минуту.
- Не копируй ключи в другие проекты «чтобы попробовать». Нужен доступ — скажи.

Какие переменные нужны и зачем — см. `docs/ENV.md`.
