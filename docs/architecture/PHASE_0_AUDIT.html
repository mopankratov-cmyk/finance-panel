Current vs target responsibility

Hermes CEO

Goal intake, workflow choice, decomposition, Evidence Pack consumption, final verdict. No state-machine ownership or protected executor access.

Workflow Engine

Target owner for versioned process-specific sequences/DAGs, transitions, retry/reclaim, artifacts, reviews, gates and audit events.

Security Runtime

RuntimeSecurityContext, one spawn factory, profile OS isolation, env policy, brokered credentials and owner-only refresh.

Persistent profiles

Registered durable employees with isolated HOME/UID/container/ACL and explicit grants. Work exchange through workflow/artifacts.

Temporary subagents

Short-lived children with subset capabilities. Not durable workers, independent reviewers or security boundaries.

Cockpit

Read model and human decisions through a narrow BFF. No browser-held model/dashboard token and no direct LLM or PTY.

Implementation admission criteria

  1. Approve all nine ADRs and assign component owners.
  2. Approve process-specific template contracts and dynamic Cockpit rendering; no hard-coded business workflow.
  3. Select workflow datastore, OS isolation mechanism, credential backend, human identity and artifact storage.
  4. Demonstrate a fail-closed runtime-enabled gate on start, retry, reclaim, reconnect and restart.
  5. Pass synthetic sentinel tests across terminal, background process, execute_code, MCP and every delegation variant.
  6. Prove named profiles cannot read root auth/HOME or receive gateway-only credentials.
  7. Prove OAuth refresh changes only the owning versioned record.
  8. Preserve PATH, isolated HOME, TMPDIR, LANG, SHELL, NO_PROXY, no_proxy and exact task-scoped Hermes fields.
  9. Bind reviews and Human Gates to immutable artifact manifest hashes.
  10. Keep the default gateway unchanged until isolated offline tests and an explicitly authorized rollout pass.
