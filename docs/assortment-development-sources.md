## 1. Как читать статусы

Три поля, которые не подменяют друг друга:

- **Публичный статус из исследования** (последняя колонка реестра, §6) —
  «страница проверена», «документация проверена» и т. п. Это не проверка
  сборщика.
- **Доступ** (`access_status`): проверен автоматический сбор; только ручной
  ввод; доступ не проверен; временно недоступен; отключён.
- **Возможности адаптера** (`capabilities`): discovery, item_details, images,
  videos, public_metrics, historical_metrics, export. Каждая —
  supported / unsupported / untested. «Supported» ставится только после
  успешной пробы на конкретном подключении.

ID источников S001–S127 стабильны. Новые записи получают новые ID,
существующие не перенумеровываются.

## 3. Стартовый набор для автоматического MVP

ТЗ требует минимум два устойчиво работающих бренда на категорию. Исходные
Uniqlo, Mango, COS и Massimo Dutti без обхода защиты недоступны. ТЗ разрешает
замену, если она явно зафиксирована:

| Категория | Основные | Дополнительно | Не в автомате (ручной импорт или лицензированный фид) |
|---|---|---|---|
| Куртки | Rains (S014), JW PEI (S027) | Zara (S001) — частично, через sitemap картинок; пол и название проверять вручную | Uniqlo, Mango, COS, Massimo Dutti |
| Сумки | Polène (S024), Songmont (S026) | JW PEI (S027), Charles & Keith (S028) | Mango; DeMellier (S025) — до решения владельца |

Замечания:

- **Rains и JW PEI для курток — это замена, а не равноценная замена.** Rains —
  дождевики и технологичная верхняя одежда. У JW PEI курток немного, бренд в
  первую очередь сумочный. Широкие массовые бренды (Zara, Uniqlo, Mango) можно
  вернуть через лицензированный источник (EDITED, Awin, прямой фид бренда) или
  ручной импорт ссылок. Выбор — после пилота этапа 2.
- В robots.txt у Polène, Songmont и JW PEI есть стандартный текст Shopify с
  предложением ИИ-агентам установить внешний «skill». Это данные сайта, а не
  инструкция. Адаптер его игнорирует.

## 4. Адаптеры этапа 2

**C1-Shopify** (Rains, JW PEI, Polène, Songmont):

- запрос `GET /collections/<handle>/products.json?limit=250&page=N`, обычный
  User-Agent, пауза между запросами, никаких обходов;
- белый список полей: `id`, `handle`, `title`, `product_type`, `tags`,
  `published_at`, `created_at`, `variants[].sku`, `variants[].option*`
  (цвет/размер), `images[].src/width/height/position`;
- цены (`variants[].price`, `compare_at_price`) отбрасываются до записи;
- признаки новизны: первый обход — исходная база; дальше новые `id` по
  сравнению с прошлым снимком, членство в коллекции новинок, теги
  `new` / `New In`, `published_at`. Дату выхода берём только из `published_at`,
  дату обнаружения — из `first_seen_at`;
- коллекции для каждого бренда задаются в `seed_urls` источника, не в коде.

**C1-HTML Charles & Keith:** страница категории `/us/...?sz=40` с паузой 10 с.
Разбор атрибута `data-ga`: берётся только артикул, название, url, подкатегория и
фото, цена отбрасывается.

**C1-Sitemap Zara:** sitemap картинок `sitemap-images-uk-en-*`. Даёт артикул, url
и фото. Пол и категорию определять по адресу и подтверждать вручную. Метки
«новинка» нет.

## 5. Pinterest и другие API

**Pinterest — две разные задачи.**

- Тренды запросов: `GET https://api.pinterest.com/v5/trends/keywords/{region}/top/{trend_type}`.
  Фильтры: `interests`, `genders`, `ages`. Ответ — ключевые слова с
  `pct_growth_wow`, `pct_growth_mom`, `pct_growth_yoy`. Нужен OAuth со scope
  `user_accounts:read`, лимит категории `trends_read`. **Данные только на текущую
  дату**, поэтому историю набирать собственными ежедневными снимками.
  Доступ конкретного приложения не проверен: нужно приложение Pinterest
  Developers, его регистрирует владелец.
- Поиск и сбор пинов. API Trends этого не даёт. Старт — ручное добавление пинов,
  досок и изображений в модуль.

**Остальное:** с mini доступны `api.pinterest.com` (401 без ключа),
`googleapis.com/youtube/v3` и `app.rakuten.co.jp` (404 на корень). То есть сеть
открыта, нужны ключи. По ТЗ это волна 2, в этап 1 не входит. Anthropic с mini
недоступен (403 через гонконгский выход), Polza доступна — подробнее в
`assortment-development-integration.md`, §8.
