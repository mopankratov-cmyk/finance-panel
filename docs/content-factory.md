## 0. Что делает завод

Из товара маркетплейса (WB/Ozon) автоматически собирает короткие видео (рилсы) для набора аудитории и трафика на карточку. Конвейер: **подготовка → рецепт → генерация → монтаж → рендер → ОТК → банк → постинг → метрики → A/B → размножение винеров**.

Экономика — **winner-экономика**: заранее не угадать, что залетит; выручку даёт объём попыток × петля, которая находит и множит выстрелы. Деньги не узкое место (себес ролика $0.6–3, потолок $10–15), узкое место — **хит-рейт + объём + качество исходника**.

---

## 1. Архитектура: два слоя

**Предпроизводство (prep, upstream)** — готовит переиспользуемые входы ОДИН раз на товар/нишу, вне рецепта:
1. **Анализ ниши** → playbooks / visual-profiles (что залетает: хуки, структуры, темп) → вход для построения рецептов.
2. **Подготовка товара (source-prep)** → библиотека чистых рендеров товара → вход для нод/генерации.

Симметрия: анализ ниши готовит «что снимать», source-prep — «из чего снимать». Оба ДО рецепта.

**Производство** — рецепты/ноды потребляют подготовленное: autofill → генерация (из чистой библиотеки) → монтаж → рендер → ОТК → банк.

**Контур обучения** — постинг → метрики → A/B (ab-rank) → размножение винеров (reel-recompose).

## 2. Предпроизводство

### 2.1 Анализ ниши (есть)
Разведка виралок (Virlo/MPStats), `niche_playbooks`, `niche_visual_profiles`, хук-турнир. Выдаёт рецепту: структуру, хуки, эстетику съёмок ниши.

### 2.2 Подготовка товара — source-prep (ТЗ, СТРОИТСЯ)

**Проблема (корень, выявлен 2026-06-22):** для fashion/фото-only категорий (одежда, сумки) видео-контента ноль, а WB-фото — **сплошь инфографика** (текст/плашки/watermark на КАЖДОМ кадре). Если кормить такое в i2v — текст уезжает В видео = «оживший листинг». Узкое место видео — **НЕ движок** (seedance/kling работают), а **чистый источник**. Доказано вживую (CLR01012 CLÉRIN): remove-bg вычистил инфографику → seedance i2v дал чистый клип за 62с.

**Стадия (условная — запускается, если источник не generation-ready):**

```
WB-фото → [1 detect] → если грязь:
  [2 bg-removal] → [3 inpaint текста НА товаре] → [4 stage+relight] → [5 upscale] → [6 smart-crop 9:16]
→ N чистых рендеров (hero / деталь / ракурс / сцена) → [7 store disk='prepared']
```

**Маппинг шаг → сервис/модель (с фолбэками; всё доступно из РФ — MPStats нативно, fal уже интегрирован):**

| # | Шаг | Основной | Фолбэк | Примечание |
|---|---|---|---|---|
| 1 | detect generation-ready | эвристика text-density / Claude-vision («чистый кадр или инфографика?») | при сомнении → чистить | дёшево; не чистить съёмку/чистый каталог |
| 2 | удаление фона | fal BiRefNet / RMBG | MPStats `remove-bg` | текст в полях/фоне уходит вместе с фоном |
| 3 | inpaint текста на товаре | fal inpaint (LaMa/SDXL) / Flux Kontext «убрать текст, сохранить товар» | MPStats `freeform` | только если плашка лежит НА товаре |
| 4 | стейдж + релайт | MPStats `in-action`/`replace-bg` (сцены) ИЛИ fal **IC-Light** (свет под сцену) | белый/градиент-фон | IC-Light = «не вклеено»; решающий для реализма |
| 5 | апскейл | MPStats `upscale` / fal clarity-upscaler | пропустить | до sweet-spot разрешения i2v-модели |
| 6 | smart-crop 9:16 | своя эвристика (центр по bbox маски из шага 2) | center-crop | запас под движение камеры |
| 7 | store | Supabase бакет `prepared/<article>/<variant>.png` + строка `content_assets` `disk='prepared'` | — | durable библиотека (как clip-library) |

Каждый шаг best-effort с фолбэком → пайплайн не падает; при полном провале — наименее-плохой вариант + флаг.

**Хранилище:** `content_assets`, `disk='prepared'`, теги артикул/ракурс/сцена/качество. Это библиотека рендеров товара, переиспользуется во всех рецептах/вариантах этого товара (reuse-экономика).

**Триггер:** upstream — на новый товар / батч-кнопкой / кроном, ДО запуска рецептов. Либо лениво: рецепт стартует → нет `prepared` для артикула → сперва прогнать prep.

**Правка `assetBind` (lib/factory/assetBind.ts):** приоритет привязки источника к нодам:
`prepared` (чистое) → real-съёмка (диск) → сырое WB (фолбэк). Ноды перестают видеть инфографику.

**Подготовка изображений «под нейронки» — два семейства (для справки):**
- *Подготовка исходника:* bg-removal (BiRefNet/RMBG/SAM2/rembg), inpaint (LaMa/Firefly), upscale (Real-ESRGAN/clarity/SUPIR), релайт (**IC-Light**), стейдж (Photoroom/Pebblely/MPStats/Flux Kontext), smart-crop.
- *Подготовка условий генерации:* **ControlNet** (canny/depth/normal — сохранить форму), IP-Adapter (идентичность по референсу), маски. Для i2v условие = сам стартовый кадр + preservation-промпт; depth-кондишн полезен для детальных товаров.

**Build vs buy:** turnkey e-com сервисы (Photoroom, Claid.ai, Flair.ai, Pebblely) делают предподготовку целиком, но глобальные → РФ-оплата проблемна. Рекомендация: **compose на MPStats (нативно РФ) + fal (уже интегрирован)** — доступно, дёшево внедрить, надёжно по сети. Turnkey — только если качество ощутимо выше (проверять тест-кадром).

## 3. Производство (pipeline)

Машина-исполнитель: `lib/factory/graphRun.ts` (self-chaining граф) + `app/api/factory/graph-run/*`. Состояние в `node_recipes.run_plan` (стейт-машина: autofill → submit → gen-poll → assemble → render-submit → render-poll → otk → bank → done). Захват CAS-лизом (`claimNextRecipe`), бюджет `MAX_RENDERS`.

- **autofill** (§17 ИИ-режиссёр) — заполняет граф (инструмент/промпт/параметры на ноду). `normalizeParams` (Ф0) гарантирует API-валидность.
- **auto-bind** (`assetBind.ts`) — привязывает источник к нодам без него (после prep — из `prepared`).
- **генерация** (`nodeEngine.ts`) — диспетчер нода→движок: fal i2v (seedance/kling/pika), Creatify (UGC-актёр), ElevenLabs (RU-озвучка), disk_real (готовый клип).
- **clip-library** — на assemble `persistClips` качает готовые клипы с fal.media (эфемерно) в наш бакет `clips/`, подменяет node.url на durable, заводит `content_assets(kind='clip')` → библиотека для ре-ката.
- **монтаж** — ReelV5 (Remotion): кинетик-капшены, бит-синхронные склейки (`quantizeToBeats`), обводка, грейд, бренд-эндкард, музыка, закадр. Движок переключается `FACTORY_RENDER_ENGINE` (remotion | shotstack).
- **рендер** — Remotion render-service на Yandex VM (89.169.129.146:8080), `localizeAssets` качает remote-ассеты локально перед рендером; асет-сервер 127.0.0.1:8090. Рилс ~70с.
- **ОТК** — видео-критик (Claude по кадрам) + артефакт-гейт; балл по осям (hook/retention/native/brand/cta); реген-петля виновной ноды.
- **банк** — `gen-save`: финальный ролик в бакет `gen/` + `content_assets(kind='video')`.

## 4. Контур обучения

- **постинг → метрики** (`post_metrics`) — ⚠️ ДЫРА: автозалив на WB/TikTok/Reels + автоимпорт метрик не замкнуты (сейчас вручную). Без этого петля обучения разорвана.
- **A/B** (`ab-rank`) — ранжирует ролики по рынку → винеры (множить) / лузеры (стоп).
- **размножение** (`reel-recompose`) — 1 генерация → N монтажей (другой хук/первый кадр/музыка) из clip-library, амортизация генерации по R. Монтаж-скилл учится эмпирически: дефолты ReelV5 + варианты + A/B + редкий ручной слой (Palmier/Remotion).

## 5. Инфраструктура

- **Рендер:** Remotion VM. Узкое место скорости было I/O (диск) — решено; кнобы скорости в `render-service/server.mjs`. Токен `REMOTION_RENDER_TOKEN` (на VM и в Vercel).
- **Движки:** fal (i2v + prep-модели), MPStats Photo Editor (prep, РФ-нативно), Creatify (нужны ключи), ElevenLabs.
- **Хранилище:** сейчас Supabase Storage `factory-media` (префиксы renders/ gen/ clips/ prepared/ i2v-src/ voiceover/). Каталог = `content_assets` (абстрагирует место). На масштабе → **Cloudflare R2** (нулевой egress, критично для видео) + retention (винеры хранить, лузеров чистить).
- **Надёжность графа:** крон-страховка `/api/factory/graph-run/cron` (`*/2`) будит зависшие рецепты и гоняет шаг **синхронно** (Vercel `after()` не исполняется при server-to-server вызове — это был баг первой версии). См. уроки.
- **Сеть:** РФ-локаль владельца ходит к Vercel/GitHub/fal/VM через прокси, который **флапает** (общий инет ок); MPStats/Supabase стабильнее. git push/gh — ретраить; мёрж через `gh api -X PUT .../merge` (REST), когда graphql EOF-ит.

## 6. Ключевые уроки (durable — чтобы не наступить снова)

1. **`"picker"`-заглушка:** автофилл вписывал ИМЯ ui-контрола («picker»/«file») в ЗНАЧЕНИЕ source-полей → доезжало до Remotion как `staticFile("picker")` → 404. Фикс: `isPlaceholderSource` (toolSchemas) + normalizeParams дропает + hasSrc/submitNode трактуют как нет-источника.
2. **WB-CDN рехост («seedance 422»):** это был НЕ формат — fal через раз не мог скачать WB-фото с `*.wbbasket.ru` (file_download). Фикс: `rehostImage.ts` рехостит фото в наш бакет на ВСЕХ путях fal (nodeEngine.submitNode, /video-fal, /hybrid-compose). SSRF-гард + `redirect:"error"`.
3. **Vercel `after()` не для server-to-server:** тик графа делал работу в `after()`, который не исполняется при вызове из крона → крон-страховка гоняет `runRecipeStep` СИНХРОННО. Урок: для рантайм/платформенных багов код-ревью недостаточно — нужен живой e2e (ревью 7→0 не поймал, e2e поймал).
4. **clip-library:** i2v-клипы эфемерны на fal.media → персистить в наш бакет на assemble (ре-кат + надёжный рендер).
5. **fashion source-prep:** WB-фото = инфографика → нужна стадия очистки ДО нод (этот документ, §2.2).

## 7. Данные

`content_assets.disk`: `wb` (карточные фото), `gen` (наш вывод: kind=video финал, kind=clip кирпичики), **`prepared`** (чистые рендеры товара — новое), real-диски (Я.Диск съёмка). Каталог видео = `disk='gen'`. Прямые VM-рендеры в обход рецепта НЕ каталогизируются.
Прочее: `node_recipes`/`node_recipe_nodes` (рецепты/ноды), `generation_history` (журнал), `post_metrics`, `reel_variants`, `viral_videos`, `niche_*`, `cf_signals` (телеметрия).

---

## 8. Скилл-стек и порядок

Порядок по приоритету: **анализ+рецепты → генерация → монтаж**. НО это петля с обратной связью (сигнал качества — с рынка, с конца), а не водопад. Сначала набивать руку на анализе+рецептах (чертёж), затем генерация (из рецептов), затем монтаж (эмпирически: дефолты + варианты + A/B + ручной слой).
