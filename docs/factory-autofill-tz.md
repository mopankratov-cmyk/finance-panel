# ТЗ · «ИИ-Автозаполнение графа» (Авто-режиссёр нод) — §17

**Дата:** 2026-06-22 · **Ветка-родитель:** `feat/factory-ai-guide` · **Экран:** 03 Нод-канвас + 04 Инспектор

## 1. Зачем (одна фраза)

Сейчас на каждой ноде человек **вручную** выбирает движок (seedance/kling/creatify/disk_real/…) и **вручную** заполняет все поля настроек в Инспекторе (04), по одной ноде. Декомпозитор (`/decompose`) уже предлагает `tool_candidate`, но это лишь подсказка на канвасе — она не превращается ни в выбранный `tool`, ни в заполненные `params`.

**Хотим:** одно действие → ИИ сам routing'ует движок на **каждую** ноду графа И заполняет все настройки + промпт, опираясь на товар/бренд/нишу/доступность движков/наличие реальной съёмки. Человек дальше — **по желанию** — донастраивает любое поле. Не тронул → всё и так готово к сборке (05).

Принцип: **manual → assisted → auto.** Это шаг «auto» поверх уже готового «manual».

## 2. Что уже есть (на что опираемся, не дублируем)

| Кусок | Файл | Роль в фиче |

**Разрыв:** нет ничего, что бы (а) на весь граф разом выбрало `tool` и (б) заполнило валидные `params`. Это и строим.

## 3. Архитектура фичи

Три части: **(A)** детерминированный валидатор-нормализатор параметров (гарантия, что в API уходит только валидное), **(B)** batch-эндпоинт `/api/factory/autofill` (Claude раскладывает весь граф → нормализация → сохранение), **(C)** UI-кнопки на канвасе (весь граф) и в инспекторе (одна нода) + семантика «человек главнее».

### 3A. Нормализатор параметров (де-риск, делаем первым)

Новый чистый модуль `lib/factory/normalizeParams.ts`:

```ts
export function normalizeParams(tool: string, raw: Record<string, any>): {
  params: Record<string, any>; warnings: string[];
}
```

Логика (по `TOOL_SCHEMAS[tool]`):
1. **Whitelist** — оставить только поля, чьи `api_param` есть в схеме инструмента; остальное выкинуть в `warnings` («движок не знает поля X — отброшено»).
2. **Энумы** — если значение не из `values`, снапнуть на ближайшее по смыслу либо на `default`; залогировать.
3. **Числа/слайдеры** — clamp в `[min,max]`, снап к `step`.
4. **Дефолты** — для незаданных полей с `default` подставить дефолт (чтобы нода была полной, а не полупустой).
5. **Вертикаль-гард** — принудительно `aspect_ratio` = `9:16` (или `9x16` для creatify) — известный баг с горизонталью.
6. **i2v-гард** — для `seedance/kling` обязателен `image_url`: взять из `node.asset_url` → фото товара (по article) → если нет, вернуть warning `needs_image` (эндпоинт по нему даунгрейдит движок, см. 3B).

Цель: **что бы Claude ни нагаллюцинировал, в `node-save`/`nodeEngine` уходит API-валидный объект** → превью/`graph-run` не упадут с 422. Покрыть юнит-фикстурами на каждый инструмент.

### 3B. Эндпоинт `POST /api/factory/autofill` (§17)

**Вход:** `{ recipe_id, node_ids?: string[], force?: boolean }`
- `node_ids` нет → весь граф; есть → только эти ноды (для per-node автозаполнения из инспектора).
- `force` нет → **пропускать ноды с `human_edited=true`** (не затирать ручные правки). `force=true` → переписать все.

**Сбор контекста (детерминированно, до Claude):**
- Ноды рецепта из `node_recipe_nodes`: `ordinal, node_type, role/slot, duration_sec, onscreen_text, voiceover, visual_desc, tool_candidate, asset_url`.
- Товар/бренд: `article + name + brandProfile(article,name)`; ниша из `rubric`.
- **Доступные движки:** из `toolSchemas` (`available !== false`) ∩ балансы (`/balances` > 0). Офлайн/без денег — исключить из выбора и сказать об этом в warnings.
- **Наличие реальной съёмки:** запрос к `disk-source` по article/цвету — есть ли клип. Нет → disk_real по этой роли не предлагать, поднять seedance.
- Грундинг содержимого: `learningHints(niche)` + плейбук ниши + бренд-профиль.

**Один вызов Claude на весь граф** (batch, экономим токены). System-промпт встраивает:
- Доктрину роутинга из decompose (реальная съёмка = хребет, AI = акцент, не AI в каждую вторую ноду).
- **Точные схемы только тех инструментов, что доступны** — список `api_param` + энумы + дефолты + `hint` (чтобы Claude заполнял валидно и осмысленно).
- Гарды доступности (нельзя выбрать офлайн-движок / disk_real без клипа).
- Бренд/нишу/обучение для контента промптов и текста.

**Выход Claude (строгий JSON):**
```json
{ "assignments": [
  { "ordinal": 1, "tool": "seedance", "prompt": "англ. motion-промпт…",
    "params": { "model":"seedance", "resolution":"720p", "aspect_ratio":"9:16", "duration":5, "camera_fixed":true },
    "reason": "детальная игрушка от реального фото" }
] }
```

**Пост-обработка каждой ноды на сервере:**
1. `normalizeParams(tool, params)` (3A) → валидные params + warnings.
2. i2v без `image_url` → **даунгрейд** на `disk_real` (если клип есть) либо пометить `needs_image` (нода сохраняется, но в смете предупреждение).
3. Запись через ту же логику, что `node-save`: `patch{ tool, params, prompt }`, **но** `source:"ai_autofilled"`, `human_edited:false`; синк `graph_doc` (`status:"configured"`).
4. Сигнал обучения: `cf_signals.insert({ event:"node_autofilled", recipe_id, node_id, tool, params, reason })`.

**Ответ эндпоинта:**
```json
{ "ok": true, "filled": 6, "skipped": 1,
  "byTool": { "seedance":3, "disk_real":2, "creatify":1 },
  "cost_estimate": "≈ $0.42",
  "warnings": ["нода #4: disk_real без клипа → seedance", "creatify: низкий баланс"],
  "nodes": [ { "node_id":"…","tool":"seedance","ordinal":1 } ] }
```

Весь обработчик в `try/catch` → **всегда JSON** (как остальные роуты завода). `maxDuration = 60`.

### 3C. UI (в `public/inferno/studio.html`)

**Канвас (03)** — главная кнопка рядом с «Авто-укладка»/«Сборка»:
- `🪄 ИИ-заполнить граф` → `POST /autofill {recipe_id}`.
- Прогресс: «заполняю 6 нод…». По завершении — карточка-итог: `Граф заполнен: ▦×3 · 🎞×2 · ◔×1 · ≈$0.42 · ⚠ 1`. Перерисовать канвас — у нод загораются точки инструментов (`n.tool`).
- Если есть ноды с `human_edited` — кнопка по умолчанию их не трогает; рядом мелкий чекбокс/пункт «перезаписать ручные» (`force:true`).

**Инспектор (04)** — на выбранной ноде:
- `🪄 Заполнить ноду ИИ` → `POST /autofill {recipe_id, node_ids:[id], force:true}`. Поля инспектора пере-наполняются ответом, сверху плашка `✨ заполнено ИИ — донастрой при желании`.
- Любое ручное изменение поля + Сохранить → `node-save` ставит `human_edited:true` (как сейчас) → нода защищена от следующего общего автозаполнения.

**Проводник (панель/next-step):** когда «N нод без инструмента» — добавить CTA-кнопку `🪄 заполнить всё ИИ` прямо в карточку шага (детерминированный `nextStep` в `studio.html`, ветка `case "canvas"`).

## 4. Семантика «человек главнее» (ключевое требование)

| Состояние ноды | `source` | `human_edited` | Поведение общего автозаполнения |
|---|---|---|---|
| только из декомпозиции | `decomposed` | false | заполняется |
| заполнена ИИ | `ai_autofilled` | false | пере-заполняется (re-roll) |
| тронута человеком | `human_chosen` | true | **пропускается** (если не `force`) |

→ «ИИ заполнил всё, человек захотел — донастроил, не захотел — и так ок» выполняется буквально: повторный запуск никогда не стирает ручные правки без явного `force`.

## 5. Фазы (shippable инкрементами)

- **Ф0 · Гард.** `normalizeParams.ts` + юнит-фикстуры по каждому инструменту. Изолированно, ничего не ломает.
- **Ф1 · Ядро.** `/api/factory/autofill` (Claude batch → normalize → node-save-логика, `source/human_edited`) + кнопка `🪄 ИИ-заполнить граф` на канвасе. MVP-грундинг (node_type/role/tool_candidate/бренд).
- **Ф2 · Грундинг.** Гарды доступности (балансы + `available`), проверка реальной съёмки (disk-source) с даунгрейдом, learningHints + плейбук ниши, смета `cost_estimate` + warnings.
- **Ф3 · Per-node + петля.** Кнопка в инспекторе (одна нода, `force`), CTA в Проводнике, сигнал `node_autofilled`, защита `human_edited`.

## 6. Критерии приёмки

1. На графе из N нод без инструментов одна кнопка `🪄` → у **всех** N загораются `tool` и заполнены `params`; можно сразу идти на Сборку (05) без захода в инспектор.
2. Роутинг соблюдает доктрину: реальные роли (problem/solution/proof) при наличии клипа → `disk_real`; AI — точечно (hook/динамика/говорящая голова). Не AI в каждую вторую ноду.
3. Любая заполненная нода даёт **валидное превью** (`node-preview`) без 422 — нормализатор гарантирует параметры.
4. Движок без баланса/`available:false` **не выбирается**; в warnings — почему.
5. i2v-нода без фото товара не падает: даунгрейд на disk_real либо явный `needs_image` в смете.
6. Ручная правка ноды → повторное `🪄 ИИ-заполнить граф` (без `force`) её **не трогает**.
7. Инспектор: `🪄 Заполнить ноду ИИ` пере-наполняет поля одной ноды; человек правит любое поле и сохраняет.
8. Итоговая карточка: разбивка по движкам + смета + число предупреждений.

## 7. Риски / заметки

- **Галлюцинация параметров** — снимается нормализатором (Ф0). Claude может предлагать что угодно — в БД и API уходит только валидное.
- **Стоимость токенов** — один batch-вызов на граф, не по ноде. Per-node вызов — только из инспектора по явному клику.
- **`tool_candidate` ≠ финальный выбор** — Claude в autofill переосмысливает кандидата с учётом доступности движков и наличия съёмки (декомпозитор этого контекста не знал).
- **headless/CSS** — кнопка и плашка статичные, без transition-зависимостей (известная заметка про заморозку анимаций в headless).
