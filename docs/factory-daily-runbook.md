# Factory Daily Runbook

Статус: Milestone 4 operator run control.

Цель: каждый день выпускать ролики через один основной путь `graph-run` без возврата к legacy очередям и без ручной охоты по техническим логам.

## Утренний чек

1. Открыть Studio: `https://finance-panel-two.vercel.app/inferno/studio.html`.
2. Перейти в `Пульс завода`.
3. Проверить верхнюю карточку `Состояние завода`.
   - `штатно`: можно запускать новые прогоны.
   - `есть риск`: смотреть карточку `Что проверить сейчас`.
   - `сбой`: не запускать пачку, сначала разобрать P0/P1.
4. Проверить `Стресс 10/10`.
   - Норма: `10/10 закрыты`.
   - Допустимо: предупреждения ОТК, если MP4 сохранён.
   - Не норма: `run_fail`, таймауты, зависшие `running`.
5. Проверить `Очередь прогонов`.
   - `идёт`: не трогать, пока не подвис.
   - `подвис`: открыть граф и перезапустить только этот рецепт.
   - `предупр.`: открыть MP4, убедиться что ролик сохранён.
   - `сбой`: открыть граф и смотреть последний шаг.

## Запуск ролика

1. Открыть `База видосов`.
2. Выбрать готовый рецепт.
3. Перед отправкой `graph-run` Studio показывает ориентир сметы по нодам и потолок до `x3` на ОТК-реген.
4. Если `Пульс завода` / `/ops` сообщает низкий баланс хотя бы одного сервиса, старт останавливается. Сначала пополнить или вручную обновить баланс.
5. Нажать `старт` прямо на карточке рецепта или перейти в `Сборка · ОТК` и запустить оттуда.
6. Следить за прогоном в `Пульс завода` → `Очередь прогонов`.
7. После завершения открыть `MP4` из очереди или из библиотеки.

## Что считать успехом

Успешный MVP-прогон:

- статус `готово` или `предупр.`;
- есть `output_url` / кнопка `MP4`;
- execution log не пустой;
- ОТК ниже порога не блокирует выпуск, а остаётся предупреждением.

Неуспешный прогон:

- `run_fail`;
- нет `output_url`;
- `running` висит дольше stale-порога;
- graph-run не имеет `run_id` или execution log.

## Что не чинить первым

Не начинать день с:

- `scenario-rewrite`;
- `hook-judge`;
- `variations`;
- `recipe-variants`;
- `batch-build`;
- legacy `jobs/*`.

Эти контуры не нужны для получения MP4 в текущем MVP и должны оставаться отключёнными, пока single-run path не держит стабильный выпуск.

## Приоритеты triage

P0:

- нет возможности запустить `graph-run`;
- массовый `run_fail`;
- нет сохранения MP4;
- база недоступна для `node_recipes`.

P1:

- подвисшие running-прогоны;
- render/generation/storage ошибки в текущем окне;
- низкие балансы сервисов, потому что Studio теперь блокирует новый платный запуск при явном `balances.low`;
- critic upstream недоступен, если это начинает ломать выпуск.

P2:

- старые архивные warning/fail;
- optional worker heartbeat table;
- качество ОТК при сохранённом MP4;
- улучшение текстов, фильтров и UX.

## Вечерний чек

1. В `Пульс завода` проверить, что нет активных `run_fail`.
2. Убедиться, что все завершённые ролики открываются через `MP4`.
3. После публикации вписать реальные просмотры в карточку рецепта в `База видосов`; поле метрик появляется только у рецептов с MP4, рецепт должен перейти в `опубликован`.
4. Если были предупреждения, записать короткую причину в рабочий журнал.
5. Если делался stress-run, обновить `docs/factory-latest-stress.md`.
6. Не включать отключённые компоненты ради “быстро улучшить качество” до нового стабильного stress-pass.

## Команды разработчика

Локальная проверка:

```bash
npm run test:factory
npm run build
```

Production deploy:

```bash
npx vercel deploy --prod --yes
```

Проверка после deploy без сессии ожидаемо упирается в auth:

```bash
curl -I https://finance-panel-two.vercel.app/inferno/studio.html
curl -i https://finance-panel-two.vercel.app/api/factory/ops
```

Ожидаемо:

- Studio может вернуть `307` на `/login`;
- API может вернуть `401 Не авторизовано`;
- после логина в браузере Studio должна открыть `Пульс завода` и `Очередь прогонов`.
