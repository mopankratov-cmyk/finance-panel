## 0. Вердикт совета (читать первым — он переопределил спек)

> ### ⭐ ГЛАВНЫЙ ПРИНЦИП (закон дизайна, владелец 2026-06-20): **настраиваемо ПОД КАПОТОМ, просто СВЕРХУ.**
> - **Под капотом** — движок и data-модель моделируют, хранят и дают контроль над 100% API-настроек КАЖДОГО инструмента. Ничего не захардкожено, ни одна ручка не потеряна.
> - **Сейчас (фаза ручной калибровки):** владелец — эксперт и единственный юзер — хочет видеть и крутить ВСЕ настройки. Чем больше настроек, тем лучше результат. **Ничего не прячем.** Инспектор показывает все поля инструмента, СГРУППИРОВАННЫЕ для навигации (не плоская стена), но не скрытые.
> - **«Просто сверху» — это БУДУЩИЙ слой**, не сегодняшнее упрощение: по мере наполнения дата-стека система пре-заполняет хорошие дефолты, предлагает пресеты, сворачивает рутину → в пределе «нажми кнопку — получи результат». Это НАДстройка на том же полном движке, а не удаление ручек.
> - Прямое следствие: проектируем data-модель и инспектор так, чтобы оба режима («всё открыто» сейчас и «свернуто-просто» потом) жили на ОДНОМ движке. Поэтому per-tool JSON-Schema настроек — обязательна с первого дня.
>
> ### 🎨 Дизайн — ПРОФЕССИОНАЛЬНЫЙ (отменяет «для тупого чела»)
> Дизайн = качественный профессиональный инструмент для эксперта-владельца, НЕ «ноль терминов / одна кнопка / для нетехнаря». Это прямо ОТМЕНЯЕТ `docs/content-factory-spec.md §9 («дизайн для тупого чела»)` и его философию «граф нельзя давать, 6 ручек». Термины (хук/ОТК/нода/рендер) — норма, юзер их знает. Чистый, плотный, мощный UI уровня профи-инструмента (ComfyUI/Figma/Linear), не упрощённый мастер.
>
> ### 📊 Реальные метрики соцсети — ПОЗЖЕ (владелец 2026-06-20)
> Контур постинга→метрик (views/CTR) делаем ПОСЛЕ того, как научимся генерить реальный контент — «пока до этого далеко». Сейчас сигнал для калибровки = **корпус Virlo** (плотный, за часы). post_metrics остаётся в архитектуре data-модели (задел), но ВНЕ scope прототипа. Это согласуется с вердиктом совета «корпус = сигнал сейчас».

**Строить нод-студию — ДА (владелец прав), «корпус-первый, контроль-первый».** Вход = клон конкурента (не стена настроек), но внутри ноды — все ручки открыты.

Три переворота против наивного спека:
1. **Корпус Virlo = это и есть СИГНАЛ.** 350+ разобранных залетевших видео по нишам (beat-структуры, хуки, звуки) дают плотный сигнал за часы. «Нельзя учиться без постинга» — слишком сильно: корпус = быстрый внутренний контур; реальный постинг = медленная внешняя правда (копится параллельно, не гейт).
2. **Глубинная ценность студии — КОНТРОЛЬ/ДОВЕРИЕ + перевод экспертизы владельца в явный переиспользуемый актив**, а не «обучение агентов». Владельца сожгла чёрная коробка автогена. Студия даёт авторство и видимость — это и есть «исключительный результат».
3. **Вход = НЕ пустой холст и НЕ «опиши агенту» (это та же чёрная коробка).** Вход = **разбор реального конкурента-победителя на ноды → „Перенести себе“ → правка.** Человеком выбранный каркас.

**Не-переговорные требования совета:** счётчик стоимости рендеров + кэш превью по `hash(tool+prompt+params)` — теперь ОСОБЕННО критично (все ручки открыты → больше итераций → больше трат Seedance/Creatify; кэш не перегенерит неизменённое); **все настройки инструмента открыты и сгруппированы** (см. главный принцип — не прячем); честный звук («нет mp3 → фикс-каденс», не фейк бит-синк); предусловие-блокер — бэкфилл `content_assets.duration_sec` (ffprobe).

## 1. Что это за продукт

**V3 — нод-студия виральных видео для селлера WB/Ozon.** Единая ПРО-среда, где человек прецизионно собирает короткое видео/карусель/пост из типизированных нод-кирпичиков, на каждую ноду навешивая инструмент (Seedance / Creatify / Claude-промпт / Higgsfield / Gemini / Shotstack / звук) и его настройки. Прорыв: (1) система ВИЗУАЛЬНО ОСОЗНАЁТ ниши/товары/готовый контент; (2) сценарист-агент раскладывает залетевшее видео конкурента на ноды, владелец одной кнопкой переносит каркас себе и меняет содержимое на свой товар; (3) каждое ручное решение пишется в дата-стек → постепенный подъём автономии (manual → assisted → auto, по-нишево).

**Это НЕ переписывание бэкенда.** ~70% «осознания», все адаптеры инструментов, монтаж+ОТК+банк уже работают (Shotstack-смоук пройден — кириллица рисуется). V3 = продукт-слой (React Flow холст + node-runner + per-node инспектор) поверх выверенного assembly-движка.

## 1.5 Поток продукта (user journey) — мульти-формат это ШАГ, не параллельный столп

```
Карта осознания (маркетолог-резюме ниши: что заходит + примеры виральных + варианты контента/дистрибуции)
  → выбираешь ТОВАР
    → выбираешь ФОРМАТ:  ● Видео   ○ Карусель   ○ Статик-пост
         │
         ├─ [Видео] → разбор видео конкурентов на ноды → «Перенести себе» → нод-канвас
         │              → per-node инструмент + ВСЕ настройки → сборка (Shotstack) → ОТК → банк
         ├─ [Карусель] → разбор каруселей конкурентов на ноды-слайды → … (позже за MVP)
         └─ [Статик]  → разбор статик-постов → 1 нода-слайд → … (позже за MVP)
  → (ПОЗЖЕ) постинг + реальные метрики
```

Формат — это **развилка после карты осознания**, и она задаёт, ЧТО разбираем у конкурентов и какой набор нод/инструментов. Видео — путь MVP; карусели/статик — тот же язык нод, но позже.

## 3. Экраны (surfaces)

1. **Командный центр / Карта осознания + маркетолог-разбор** — плитки ниш (готовность: playbook / N viral_videos / реальная съёмка / шаблоны), раскрытие → товары, карточка товара (понимание + счётчики кадров/генераций + winner + пробелы). **Панель главного маркетолога по нише:** текстовое РЕЗЮМЕ «что заходит» (из niche_playbooks + Virlo-анализа + веб-ресёрча), ГАЛЕРЕЯ примеров виральных видео/постов конкурентов (ранг по virality_score), РЕКОМЕНДАЦИИ — какие виды контента делать (видео/карусель/статик + форматы) и КУДА дистрибутировать (площадки/каденс). Кнопка «собрать контент» → выбор ФОРМАТА → дальше по потоку (§1.5). *Данные: niche-playbook/cached, viral_videos, top-hooks/sounds, products, disk-source; веб-ресёрч агента.*
2. **Анализ конкурентов / Decompose** — лента залетевших (ранг virality_score), на каждое — горизонтальная лента нод (beat_structure) с иконкой инструмента-кандидата, таксономия формата (enum), раскрытие ноды (role/hook_type/onscreen/voiceover/emotion/duration), кнопка **«Перенести ноды себе»**. Карусель: panel_texts[] как ноды-слайды. *Данные: viral_videos.beat_structure/analyzed_full, Virlo analyze_video.*
3. **Нод-канвас** — React Flow: ноды-карточки (мини-превью + статус-бейдж + ОТК), типизированные цветные порты (video/audio/image/script/caption/product, невалидные связи блокируются), слот инструмента на нижнем порту, палитра+поиск, минимап, **НЕ пустой холст** (старт с клона конкурента/шаблона), кэш превью по hash.
4. **Инспектор ноды** — правый сайдбар, **ВСЕ настройки инструмента видны, СГРУППИРОВАНЫ по смыслу** (генерация / камера-движение / звук / композиция / служебное) — ничего не скрыто (главный принцип). Группы можно сворачивать визуально, но это организация, не сокрытие. Поля адаптируются под инструмент (per-tool JSON-Schema), крупный редактор промпта, счётчик цены и кнопка «сгенерировать превью» (кэш по hash). На выходе ПИШЕТ теги content_assets + событие cf_signals (включая ВСЕ выставленные params — это и есть дата-стек).
5. **Сборка / Таймлайн / ОТК** — дорожки video/ugc/animation/sound/music/captions, суммарный хронометраж + наложение звука + per-clip transition/effect, кнопка «Смонтировать» → buildEdit→Shotstack, панель ОТК (5 осей + verdict + issues + fixes, **включая фейлы<8**), «беру / не то» + чипы-причины → дата-стек.
6. **База видосов / Библиотека рецептов** — галерея результатов (фильтр ниша/формат/confidence), версии графа (форк родитель→потомок для A/B), библиотека пресет-нод/шаблонов, экран «Рост» (post_metrics), наблюдаемость стоимости рендеров.

## 4. Модель нод-графа

**Два уровня (урок ComfyUI):** `graph_doc` (UI-снимок: позиции/цвета/раскрытия/превью/статусы) ОТДЕЛЬНО от `run_plan` (плоская мапа node_id→{tool,prompt,params,deps} для исполнения очередью).

```
NODE: { id, type: node_type_enum, position{x,y}, size,
  data: { tool: tool_enum, prompt, params: {по JSON-Schema инструмента},
          preview{url,kind}, status: draft|running|ready|qc_pass|qc_fail, qc_verdict },
  inputs: [Port], outputs: [Port], collapsed, color }
PORT: { id, role: source|target, dataType: video|audio|image|script|caption|product, position }
       // соединять можно только совпадающий dataType (типобезопасность блокирует невалид в UI)
EDGE: { id, source, sourceHandle, target, targetHandle, type: smoothstep }
       // поток слева-направо = монтаж/тайминг; вертикальные связи внизу = привязка инструмента/звука (n8n cluster)
NODE_TYPE enum (role-слоты hook→problem→solution→proof→cta):
  hook_ugc, ai_product_render, talking_head, prank, before_after, pov, b_roll,
  captions, sound, music, carousel_slide, static_post
  // каждый несёт дефолтный инструмент + порты + шаблон промпта + дефолтные настройки
```

## 5. Модель данных (новые таблицы)

- **`node_recipes`** (граф-голова): id, article, niche (`nicheFromArticle` — ЕДИНЫЙ ключ, НЕ бренд), mode (audience|sell), format_detected, source_viral_video_id FK (если перенесён), parent_graph_id (форк/версия), built_by (manual|assisted|auto), otk_verdict jsonb (5 осей + verdict + issues + fixes, **включая фейлы<8**), otk_score, render_id, output_url, status (draft|otk_pass|otk_fail|posted), recipe_confidence 1-5, graph_doc jsonb, run_plan jsonb. Индексы (niche, recipe_confidence desc, otk_score desc), (built_by), (status).
- **`node_recipe_nodes`** (строка-на-ноду — КЛЮЧЕВАЯ для обучения): recipe_id FK, ordinal, slot, tool, prompt, params jsonb (ВСЕ настройки), asset_id FK content_assets, duration_sec, source (human_chosen|agent_suggested|transferred_from_corpus), human_edited bool, **agent_suggestion jsonb** (что агент предлагал ДО правки — золото для обучения). Индекс (niche, slot, tool) через join.
- **`node_templates`** (шаблоны из анализа конкурентов): source_video_url, format_type, nodes jsonb[], niche.
- **`cf_signals`** (журнал событий — центральный дата-стек): {event(generated|approved|rejected|published|metrics), node_id, slot, tool, params, niche, article, mode, axes(5 осей ОТК), engine, format, sound_id, reason_chip}. Включая фейлы<8 (сейчас испаряются).
- **`post_metrics`** (контур постинга): recipe_id FK, platform, posted_at, views, watch_rate, ctr_card, saves.

Расширить: `content_assets` теги {asset_type, role, emotion, **duration_sec (ffprobe!)**, beat_suitable} — БЭКФИЛЛ при индексации (сейчас пусты, блокер #1). `winner_learnings` → полный слот-граф (сейчас только хук → компаундинг по нодам невозможен).

## 7. Лестница автономии (manual → assisted → auto)

- **MANUAL** — человек строит весь граф, агент молчит, всё логируется (наполняем дата-стек).
- **ASSISTED** — агент предлагает граф через `agent_suggestion` на каждой ноде, человек правит, `human_edited` фиксирует ЧТО изменено.
- **AUTO** — агент собирает, человек только ОТК-вердикт.
- **Флаг built_by ПО-НИШЕВО**, не глобальный рубильник. Подъём — когда accept-rate в assisted стабильно высок.
- **Обучение стартует с RETRIEVAL** (работает на десятках примеров, без fine-tune): сценарист — выборка node_recipes WHERE niche=X AND recipe_confidence≥4 → few-shot; настройщик нод — retrieval (niche,slot,tool) из node_recipe_nodes WHERE human_edited=false → реальные params, давшие native≥7. Fine-tune — позже, когда retrieval-few-shot перестаёт улучшать accept-rate.

5. **Инспектор для 2-3 инструментов** (Seedance + Creatify + Shotstack) — **ВСЕ их настройки**, сгруппированы (не только ключевые — главный принцип). Per-tool JSON-Schema.

**ПОЗЖЕ (за MVP):** **контур постинга + ввод метрик** (владелец: после реального контента); мульти-формат карусели/посты (разбор с нуля); полный набор 30+ настроек Creatify (по принципу — но итеративно); assisted/auto; fine-tune; A/B-бандит; Shotstack Templates+merge; шаринг-библиотека.

## 9. Reuse vs Build

**REUSE (есть):** все адаптеры инструментов (изоморфны submit→token→poll); очередь jobs.ts (lease, renderCount/composeCount≤3); корпус viral_videos/hooks/playbooks; ОТК video-critic+rubric; nicheFromArticle; Shotstack (смоук пройден, кириллица ✓); банк gen-save+Storage; brandProfiles; канонический Block из factory-shotstack-tz.md.

**BUILD (новое):** React Flow холст + ноды-карточки + типизированные порты + инспектор + таймлайн-зона; **node-runner** (переворот per-video→per-node: route/engine на КАЖДУЮ ноду, Shotstack=сборщик графа); 3 таблицы + cf_signals; **Decomposer Agent** `/api/factory/decompose` (POST {url|video_id} → типизированные ноды); per-tool JSON-Schema настроек (вынос захардкоженных params); бэкфилл duration_sec+теги; winner_learnings → полный слот-граф; контур post_metrics.

## 10. Риски и митигации

| Риск | Митигация |
|---|---|
| Over-scope (полный нод-резолвер+Templates+бандит сразу, base rate 60%+ провал) | Тонкий срез на 1 нише; флаг; фазы |
| Голый граф-холст = смерть продукта для нетехнаря | Вход = клон конкурента (не пустой холст); настройки ОТКРЫТЫ, но СГРУППИРОВАНЫ (организация, не сокрытие); ПРО-режим для эксперта-владельца; «просто сверху» = будущий слой обучения |
| **Блокер тегов:** duration_sec=null, теги пусты | Бэкфилл ffprobe ПЕРВЫМ — предусловие |
| Обучение без реального сигнала = фикция | Корпус Virlo = быстрый сигнал СЕЙЧАС + post_metrics ручной контур (внешняя правда) |
| Звук немой (нет mp3) | Честно «фикс-каденс», звук = инструкция при постинге; решать через generate_audio (Kling v3)/Creatify background_music позже |
| Стоимость платных API при ручной итерации | Счётчик цены + кэш превью по hash(tool+prompt+params) — non-negotiable |
| beat_structure не типизирован | Нормализатор формы ответа ПЕРЕД маппингом в ноды |
| Keyspace разорван (бренд vs ниша) | Унифицировать на nicheFromArticle (кокпит+сервер) |
| Виральность непредсказуема | Продукт продаёт ПРОЦЕСС+обучаемость+контроль, не гарантию — управлять ожиданиями |

## 13. Decomposer-агент (сердце Req2) — спецификация

**Назначение:** превратить залетевшее видео конкурента в типизированный нод-граф, который владелец переносит себе.

**Эндпоинт:** `POST /api/factory/decompose` — `{ video_url? , viral_video_id?, niche? }` → `{ ok, format, nodes:[Node], confidence, template_id }`.

> ⚠️ **ДЕ-РИСК 2026-06-20 (проверено через Virlo MCP):** `analyze_video` отдаёт ТОЛЬКО статистику
> (percentile/outlier_score/performance_label), НЕ покадровую структуру, и стоит $0.50. **Virlo НЕ даёт
> beat_structure** — поле `viral_videos.beat_structure` пустое не случайно. **Decompose раскладывает из ОПИСАНИЯ**
> (Virlo отдаёт `caption`/`description` — у виральных видео он описывает весь питч) + hook + format через Claude.
> Реализовано так в `app/api/factory/decompose/route.ts`. Позже — vision-разбор реальных кадров (Claude/Gemini vision) для точности.

**Конвейер:**
1. **Взять ОПИСАНИЕ** видео: из `viral_videos.caption` (по `viral_video_id` или топ по нише), либо передать `description` напрямую. (НЕ звать analyze_video — он без структуры и платный.)
2. **Восстановить структуру** из описания (LLM-инференс): Claude по описанию+хуку+формату восстанавливает вероятную покадровую раскладку:
   ```
   NormBeat = { ordinal, duration_sec, role:hook|problem|solution|proof|cta,
                hook_type, onscreen_text, voiceover, emotion, visual_desc }
   ```
3. **Определить формат** (таксономия enum): `ugc_anim | ai_render | prank | talking_head | before_after | pov | unboxing | reaction | problem_solution | carousel | static` — по совокупности beats (есть лицо-актёр→talking_head/ugc; reveal продукта→ai_render; до/после кадры→before_after…).
4. **Маппинг beat → node_type + tool_candidate** (таблица в коде):
   | beat-сигнатура | node_type | tool_candidate |
   |---|---|---|
   | актёр говорит, лицо в кадре | hook_ugc / talking_head | creatify |
   | крупный показ/ревил товара | ai_product_render | seedance (i2v от фото) |
   | до/после, два состояния | before_after | seedance (end_image_url) |
   | реальная съёмка-демо | b_roll / scene | disk_real |
   | текст на экране весь ролик | captions | shotstack |
   | трендовый звук | music | sound |
   | слайд карусели | carousel_slide | sharp/higgsfield/gemini |
5. **Собрать Node[]** (модель §4) с `source=transferred_from_corpus`, тайминги из NormBeat, слоты `asset_url/prompt/params` ПУСТЫЕ («вставь инструмент»).

**Промпт-подход:** Claude (sonnet) с системным промптом «ты сценарист-декомпозитор: разложи видео на типизированные кирпичики», few-shot на 3-5 заранее размеченных примерах, СТРОГИЙ JSON-выход (валидировать схемой; при обрыве — толерантный парсер как в scripts).

**«Перенести себе»:** `POST /api/factory/recipes` из template → `node_recipes` + `node_recipe_nodes`: копирует структуру/тайминги/role/hook_type, ОБНУЛЯЕТ content (asset_url/prompt/params), перемапливает niche/article на товар владельца. Копируется КАРКАС, не пиксели.

**Fallback:** beat_structure пустой/непарсимый → вернуть generic-каркас по format-таксономии (типовой граф формата), пометить `confidence:low`.

## 14. Маркетолог-агент (расширение Req1) — спецификация

**Назначение:** полный разбор ниши на карте осознания — что заходит, примеры, рекомендации контента и дистрибуции.

**Эндпоинт:** `GET /api/factory/niche-brief?niche=X` (кеш как niche_playbooks, обновляет corpus-cron еженедельно) → структурированный бриф:
```ts
NicheBrief = {
  summary: string,                              // 3-5 предложений: что реально заходит
  top_formats: [{ name, why, example_video_url }],
  content_recommendations: [{ type: 'видео'|'карусель'|'статик', format, rationale }],
  distribution: [{ platform, cadence, note }],   // куда и как часто постить
  viral_examples: [{ url, score, why }],         // галерея примеров
  updated_at
}
```

**Источники (агрегирует):** `niche_playbooks` (winning_formats, structure_by_seconds, render_role), `viral_videos` (топ по virality_score), `viral_hooks`, `top-sounds`, + **веб-ресёрч** (WebSearch «что залетает в нише X на TikTok/Reels 2026») для свежести. LLM сводит в бриф.

**UI:** панель на экране 1 (§3.1) — текст-резюме + галерея примеров (кликабельны) + чипы рекомендаций контента/дистрибуции.

## 15. API-контракты новых эндпоинтов

Все: `export const dynamic="force-dynamic"`, `maxDuration`, **весь обработчик в try/catch → ВСЕГДА JSON** (урок сессии — не отдавать платформенный «An error occurred»).

| Эндпоинт | Метод · вход | Выход |
|---|---|---|
| `/api/factory/decompose` | POST `{video_url?\|viral_video_id?, niche?}` | `{ok, format, nodes[], confidence, template_id}` \| `{status:'analyzing'}` \| `{error}` |
| `/api/factory/recipes` | POST `{template_id\|graph_doc, article, niche, mode}` | `{ok, recipe_id, graph_doc}` (создаёт черновой граф) |
| `/api/factory/node-preview` | POST `{tool, prompt, params, inputs}` | `{ok, preview_url, cost, cached:bool}` (кэш по hash; превью ОДНОЙ ноды) |
| `/api/factory/graph-run` | POST `{recipe_id}` | `{ok, job_id}` — ставит в очередь; per-node исполнение через jobs/tick (route/engine на КАЖДУЮ ноду, Shotstack=финальная сборка); статус через существующий status-роут |
| `/api/factory/niche-brief` | GET `?niche=` | `NicheBrief` (§14) |
| `/api/factory/tool-schema` | GET `?tool=` | `{ groups:[{group, fields:[{name, api_param, type, values, default, ui_control}]}] }` — JSON-Schema для рендера инспектора |

**node-runner (graph-run):** переворот per-video→per-node. Каждая нода = шаг очереди (как текущие render-шаги, гарды renderCount/composeCount≤3). Зависимости нод (edges) определяют порядок. Финальная нода shotstack_assemble собирает все готовые ассеты по таймингу → ОТК → банк.

## 16. UX-состояния (обязательны на каждом экране — «никогда не голо»)

**Общие паттерны:** loading = skeleton (не пусто); empty = что сделать дальше (CTA, не белый экран); error = реальный текст + «повторить»; generating = прогресс ноды + счётчик цены.

| Экран | loading | empty | error |
|---|---|---|---|
| Карта осознания | skeleton плиток | «синкни орбиты / собери плейбук» | текст + ретрай |
| Маркетолог-панель | «маркетолог изучает нишу…» | «нет данных по нише — запусти разбор» | текст |
| Decompose | «анализирую видео (~15-20 мин если ново)» | «нет залетевших в нише» | текст + ретрай |
| Нод-канвас | — | **холст пустым НЕ бывает** (старт с клона/шаблона) | нода: статус qc_fail/ошибка на карточке |
| Инспектор | «загружаю настройки инструмента» | — | невалид-значение подсвечено |
| Сборка/ОТК | «монтирую (Shotstack)…» / «ОТК проверяет…» | — | композиционный дефект (дыра/чёрный кадр) + ретрай |
