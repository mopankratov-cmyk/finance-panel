## Корневая причина

Дефолтный путь производства = «Seedance анимирует фото товара → оверлей хук-текста». Это
структурно даёт ровно те 4 дефекта: движущийся глянцевый рендер товара ЕСТЬ реклама, а
AI-i2v статичного объекта — источник артефактов. Плейбук завода это уже знает
(`app/api/factory/niche-playbook/route.ts:80` — AI-рендер должен быть кадром-вставкой/обложкой
внутри живого формата), но `app/api/factory/produce/route.ts:43` дефолтит `ai_generation_ref`
целым роликом. Завод противоречит собственному плейбуку.

## Стратегический разворот

**Реальная съёмка — хребет ролика. AI — только акцент (вставка/обложка). Хук и звук — рычаги виральности.**
Маршрутизация по наличию материала, а не «AI по умолчанию».

# ВОЛНА U — AI UGC с товаром (итерационная лестница)

Сигнал владельца: AI-UGC видео (говорящий актёр) ЗАШЛО («прикольно»), но БЕЗ товара в кадре —
это был режим Creatify `lipsyncs`. Цель: тот же живой UGC, но с УБЕДИТЕЛЬНЫМ показом товара.
Принцип лестницы: стартуем от того, что сработало, и добавляем фиделити товара ступенями —
дешёвое и надёжное раньше, артефакто-опасное позже. Каждая ступень — тестируемый эксперимент
(→ ОТК → постинг → метрика → лучшая ступень побеждает).

## ВЫВОДЫ ВНЕШНЕГО РЕСЁРЧА (вклеено 2026-06-19, с источниками)

**Главная развилка:** Лагерь A (AI ЗАНОВО рисует товар — Creatify Asset Gen, Arcads, Topview) →
плывут лого/текст/форма → для WB/Ozon БРАК (покупатель сверяет с карточкой). Лагерь B (инструмент
монтирует ТВОЙ реальный кадр товара как b-roll, AI делает только говорящую голову) → товар 100%
настоящий. **Наш правильный путь — Лагерь B: AI-актёр = только хук+эмоция (~10%), реальный товар
с дисков = b-roll (~90%).** Это и есть U2 — теперь ПЕРВИЧНАЯ ступень, не U1.

**⚠️ КРИТИЧНО — Creatify API:** ресёрч говорит, что (1) **API доступен только на Enterprise**, не на
Starter/Pro; (2) Starter = $39/100 кредитов, $99 = Pro/300 (НЕ 500); (3) свой реальный b-roll через
API подсунуть НЕЛЬЗЯ — только URL-парсинг, заточенный под Amazon/Shopify (WB не гарантирован);
(4) Asset Generator перерисовывает товар. → НАШ построенный `/api/factory/ugc-creatify` может НЕ
РАБОТАТЬ на купленном плане. **Перед ночью: проверить реальный тариф/доступ к API у владельца** (см.
память [[creatify-ugc]] — там $99/500/Starter, расходится с ресёрчем; live-проверка обязательна).
Если API недоступен — Creatify только как ручной UI-генератор talking-head, не в авто-заводе.

**Альтернативы под РЕАЛЬНЫЙ товар + RU (лучше Creatify для нашей задачи):**
- **Captions/Mirage** (~$10/мес) — монтирует ТВОЙ b-roll + отдельный Russian TTS. Прямое попадание в диск-стек.
- **JoggAI** ($29) — явный славянский/RU липсинк; product-avatar.
- **HeyGen Product Placement** (~$24-29, ключ у нас ЖИВОЙ) — лучший «актёр держит товар», но крупный
  товар ужимается, этикетки без гарантий → только handheld (косметика/гаджеты/упаковка).
- **Arcads** ($110) — топ-актёр, но товар НЕ показывает → только talking-head хук.

**Техники «реальный товар в AI-UGC» (ранжир эффект/сложность):**
1. **Talking-head + интеркат РЕАЛЬНЫХ кадров товара** (наши диски). Эффект макс / сложность низкая → U2.
2. **Nano Banana (Gemini 3 Pro Image) композитит реальный товар в кадр → fal Seedance/Kling i2v.**
   КЛЮЧ: после склейки залить реальное фото товара с промптом «upscale product using real photo as
   guide for fine details» (вернуть резкое лого) → потом анимировать. Эффект высокий / сложность средняя
   → это НОВЫЙ U4 (вместо inpaint). **Flux Kontext для товара-в-руке НЕ использовать** (arXiv 2603.02210
   — выдаёт отдельную картинку товара, теряет детали).
3. **Kling Omni/Elements multi-image** (актёр+товар одним вводом) — ТОЛЬКО простые/жёсткие формы
   (бутылка/коробка/бластер), не детальные игрушки/мелкий текст; обязательны негатив-промпты → U3-вариант.
- **Анти-паттерн:** one-shot i2v «актёр держит товар» — самый ненадёжный (детали плывут тем сильнее,
  чем ближе план и дольше движение). Не делать целым роликом.

## ПРОДАКШН-СПЕКИ (вшить в scenario + jobs/tick + ОТК)
- **Микс 90% реальный товар-b-roll / 10% talking-head.** Аватар только в hook (0-3с) и на эмо-битах.
- **Скелет 30с:** Hook 0-3 → Problem 3-8 → Solution+демо 8-20 → CTA 20-25; cut-down 9-15с для TikTok.
- **Темп:** резка каждые 1.5-2с (TikTok)/2-3с (Reels) первые 10с; ничего статичного дольше 4с;
  jump-cut talking-head прятать под товар-b-roll. Текст-оверлей 3-7 слов в 1-м кадре + субтитры всегда (+12% retention).
- **Негатив-промпты в рендер (−40% артефактов):** товар `blur, melted edges, mirrored text, deformed
  packaging, floating product`; человек+товар `warping fingers, frozen lips, plastic skin, head shake`.
  Макс 5-8 терминов, важнейшие первыми (Kling сильнее весит ранние).

## ОТК-ГЕЙТЫ — расширить P0.3 этими правилами
- Авто-отбраковка кадров с **mirrored text / floating product / melted edges / deformed packaging** —
  частые маркеры слопа на товаре (усиливает де-AI флор).
- Метрики-цели (для петли winners P2): **hook-rate >25-30%** (иначе хук в утиль), **retention ≥60%**.
- **Анти-AI фильтр на СКРИПТ** (палится речь, не картинка): требовать сокращения/филлеры/оборванные
  фразы/личные детали/мягкий CTA. Бан-фразы UGC: «changed my life», «I was skeptical but», «obsessed».
- **Мёртвые форматы 2026** (палятся как реклама): ring-light testimonial, forced-enthusiasm demo,
  talking-head «3 причины купить». Вместо: scenario/POV drop-in, honest review/unboxing-реакция,
  third-person social proof, contrarian, reveal/teaser (+41% watch time в кейсе).

aifire.co (Nano Banana+Kling), arxiv 2603.02210 (HiFi-Inpaint), captions.ai/russian-tts,

## U2 — Гибрид «актёр-хребет + НАШИ реальные кадры товара» (самый надёжный)

Нативный TikTok-формат (stitch/duet/реакция), товар = реальные кадры, актёр = реакция. Очень нативно.
- Критерий: сплит-композиция, реальный товар в основном кадре, реакция актёра синхронна.

- Критерий: товар в руке без деформации, лого читается, ОТК ≥8 по де-AI флору.

# ВЕРДИКТ: 3D-визуализация товара (после состязательного анализа, 2026-06-19)

**Решение: НЕ строить 3D-конвейер. В ночной автопрогон — НЕ вписывать.** Совет (5 линз: steelman ЗА/ПРОТИВ
+ cost/ROI + товары-vs-одежда + виральность; 4 из 5 → no/narrow) + скептики.

**Почему:** 3D решает *фиделити* (товар не плывёт), а НЕ *органику* — залетает хук/звук/структура (P0.2/P1.1/
P1.3), а не гладкий рендер. Проблему фиделити ночной план уже закрывает дешевле (P0.1: реальная съёмка =
хребет). 3D конкурирует не с реальной съёмкой, а с уже демоутнутым «Seedance целым роликом».

**Одежда NORVIA — категорическое НЕТ даже пилотом.** image-to-3D даёт манекен-болванку без правды кроя/
драпировки; реальная посадка ткани = отдельная физик-ниша, нерентабельно на 110+ SKU. Твои съёмки модель+
куртка (диск norvia, привязка NORVIA_LINE + цвет) честнее любого 3D → Seedance i2v / repurpose_cut.

**Жёсткие товары — узкое «да», ТОЛЬКО ручной офлайн-пилот, не код-волна.** И не generative-меш (бластеры =
глянцевый/полупрозрачный пластик + лого = classic failure-mode у Rodin/Tripo, ~40% дочинки руками), а 3DGS-
захват (Polycam/Postshot) по ТВОИМ многоракурсным фото с диска design (/МАША/УЗИ*, /Винтовка*). Только под
реально НЕВОЗМОЖНЫЙ из плоского фото проезд (360/turntable/влёт). Прозрачные флаконы — не трогать (ломает оба метода).

**⚠️ Поправка скептика (проверено по коду — важно для ночи):** «дешёвая альтернатива cut-out PNG +
motion-tracking» НЕ автоматическая. `lib/factory/falVideo.ts` `falCompose` (стр. 47-78) делает только ПЛОСКИЙ
timeline-оверлей (статичный image-трек, z-order, БЕЗ per-frame трансформа и трекинга камеры). Чтобы плашка
встала в кадр с движущейся камерой и перспективой — нужен ручной трекинг (AE/Mocha) по каждому шоту = тот же
ручной конвейер, что и 3D. **Вывод: единственный headless-путь на ночь = reference-image i2v (Seedance, уже
в `falVideo.ts`).** Cut-out-плашки полезны ТОЛЬКО для плоских/статичных композитов (slideshow, b-roll без
движения камеры — это `falCompose` уже умеет), не для движущейся камеры.

**P2.X (РУЧНОЙ пилот, НЕ в ночной автопрогон):** собрать turntable-ассет 1 hero-SKU (бластер УЗИ TT04101)
через 3DGS-захват по фото диска design (не меш) → 1 turntable + 1 «невозможный» проезд → прогнать через
video-critic/ОТК → сравнить native-балл и дрейф товара с текущим Seedance i2v. Масштабировать ТОЛЬКО если
ОТК-дельта явно положительная. До пилота кода не писать. Инструмент пилота: Polycam/Postshot (3DGS); Tripo
($0.10-0.30, e-commerce) — только если 3DGS не даст пригодного turntable. Higgsfield DoP / Seedance — дефолт
для всего остального, не трогать.

**Ночной автопрогон остаётся строго: C → R1 → P0.1 → R2/R3 → P0.2+R5 → P0.3 → R4/P1 → U2.** 3D вне ночи.

# РЕФАЙНЫ ИЗ ВНЕШНЕЙ АРХИТЕКТУРЫ (сверка 2026-06-19 — взять 4, остальное у нас сильнее)

Внешний шаблон агентов подтвердил направление (хук-турнир, variation engine, self-learning — уже в плане).
Его стек (Airtable/n8n/Runway) и чисто-AI video — НЕ брать (downgrade + воспроизводит слоп/«нет товара»).
Взять 4 prompt-уровневых рефайна:

1. **R5/niche-playbook — богаче схема извлечения формата.** К `winning_formats` добавить поля:
   `hook_type`, `structure_by_seconds` (0-2/2-5/5-10/10+), `retention_mechanism`, `psycho_trigger`,
   `attention_break_point` (где «перелом внимания»). Строже, чем текущее — продюсер/сценарист получают
   поминутную механику, а не только тему.
2. **P0.2/scripts — масштаб хуков до ~50** (сейчас 5–12) + явные curiosity-gap формулы («Ты тоже делаешь
   это неправильно…», «Никто не знает, что…», «Я проверил и вот что…»), хук ≤12 слов, разговорный. Затем
   хук-турнир отбирает топ-1..2. Хук генерится ОТДЕЛЬНО от сценария (hook ≠ video — тестируем хуки первыми).
3. **P1.2/variation engine — точная спека:** из 1 победителя делать N вариаций, меняя ТОЛЬКО
   {первые 2 сек | хук | финал | эмоция}, базовую идею НЕ трогать, по ОДНОМУ рычагу за раз (чтобы понять,
   что сработало). Цель — тест разных триггеров на объёме.
4. **scenario/P0.3 — посекундная retention-структура:** 0-2 хук → 2-5 развитие/удержание → 5-10 усиление →
   10+ неожиданный поворот/payoff; смена динамики каждые ~2 сек. Дополняет продакшн-спеки волны U.

# Factory v2 — МОДУЛЬНАЯ СБОРКА (modular content system) — целевая архитектура

Идея владельца (правильная): не «генерить один тикток», а СОБИРАТЬ видео из блоков (LEGO):
`[HOOK] + [SCENE A] + [SCENE B] + [PAYOFF] + [MUSIC] + [CAPTIONS] + [EFFECTS]`, каждый блок меняется
независимо. Это объединяет всё: реальная съёмка = хребет, AI = акцент, трендовый звук, вариации, обучение.

## Где мы УЖЕ близко (по коду)
- **Библиотека ассетов** — `content_assets` (disk/path/kind/niche/article/color/url/analysis) = скелет библиотеки. Есть.
- **Реальный контент** — `disk-source` (съёмки по артикулу) + фото карточек WB. Есть.
- **AI-контент** — `gen-save` (disk='gen'). Есть.
- **Тренд-интеллект** — волна R (виральный корпус) даёт структуру/звуки для сборки. В плане.
- **Вариации + обучение** — P1.2 + P2.1 + корпус. В плане (учиться будем на КОМБИНАЦИЯХ блоков, не только хуках).

## 3 genuinely новых куска (это и есть Factory v2)
1. **Слой тегирования ассетов** — расширить `content_assets`: `asset_type`(real/ai/utility),
   `role`(hook/scene/payoff/transition/text/broll), `emotion`(shock/curiosity/calm/flex),
   `duration_sec`, `beat_suitable`(bool), `tags[]`. Без этого Assembly Agent не выберет блок.
2. **Assembly Agent** — НЕ генерит видео, а СОБИРАЕТ структуру по секундам из тегированных блоков
   (первые 2с = сильнейший визуал; смена сцены каждые 2-3с; микс real+ai; финал=payoff/интрига).
   Новый роут `app/api/factory/assemble`. Легко (промпт + выборка по библиотеке).
3. **Движок монтажа — ВЫБРАН: Shotstack** (ресёрч + 4 линзы high-confidence + 3 скептика, 2026-06-19).
   Сейчас `lib/factory/falVideo.ts` `falCompose` умеет ТОЛЬКО плоский оверлей (без склейки/переходов/бит-синка).
   Shotstack — managed render-API: async submit→poll ложится **1-в-1 на нашу self-chaining очередь**
   (`jobs.ts`+`jobs/tick.ts`), полный JSON-таймлайн (треки+переходы+trim+audio-mux) под схему
   [HOOK]+[SCENE]+[PAYOFF]+[MUSIC]+[CAPTIONS]. **Render-воркер НЕ нужен** (рендерит в своём облаке — лимит
   Vercel обойдён физически). Резерв №2 — **JSON2Video** (если RU-шрифты/watermark подведут или тираж >190
   рендер-мин/мес → фикс $49.95/200мин). **ffmpeg-Lambda** = план миграции при кратном росте (1000+/мес).
   Creatomate отвергнут (нужен визредактор шаблона до API). Remotion+Lambda — больше devops.

   **Архитектура встройки (по нашему коду):**
   - Новый `app/api/factory/assemble/route.ts` (Assembly Agent): article+hook+mode → выбор блоков из
     `content_assets` по role/emotion/duration → Claude раскладывает по секундной сетке → возвращает
     `edit_json` (Shotstack timeline). Чистый промпт+выборка, рендер не трогает → влезает в 60с.
   - Новый `lib/factory/shotstack.ts` по образу `falVideo.ts`: `shotstackSubmit(editJson)` → render_id;
     `shotstackStatus(id)`. Тот же контракт, что `falVideoSubmit/Status`.
   - Ветка шагов в `jobs.ts`/`jobs/tick.ts`: `produce→assemble→compose-submit→compose-poll→otk→save`
     (клон submit/poll, **тот же гард renderCount≤3** против двойной оплаты). Старый falCompose-overlay —
     легаси-ветка одиночных роликов, НЕ ломаем.
   - RU-субтитры: грузить Cyrillic-TTF (Supabase Storage URL) в `timeline.fonts`, family в шаблон — иначе tofu.
   - Трендовый mp3 (P1.1) = audio-трек в том же `edit_json` (volume/trim) → отдельный audio-mux роут НЕ нужен.

   **⚠️ Поправка скептиков №1 — честная цена:** $0.20/рендер-мин ТОЛЬКО на подписке $39/мес; pay-as-you-go
   $0.30–0.40/мин + минимум, concurrency-лимит **8 одновременных рендеров**. При суб-минутных Reels расход —
   единицы $/мес, движок не меняет. НО: считать стоимость за ОДОБРЕННЫЙ ролик с учётом ретраев (renderCount≤3);
   **ОТК делать на дешёвой i2v-стадии ДО Shotstack-сборки** (compose 1 раз на клип); семафор ≤8 на стадии
   compose; смоук-тест на ПРОДЕ, не в sandbox (там watermark). Итого монтаж-слой ≈ **$39–50/мес на 200 роликов**.

   **⚠️ Поправка скептиков №2 — бит-синк ДЕМОУТ до фикс-сетки (важно, по коду):** настоящий бит-детект СЕЙЧАС
   недоставляем — Virlo отдаёт звук как id/title/avg_views, БЕЗ bpm/waveform/скачиваемого mp3
   (`trendSources.ts`/`niche-playbook:87`); beat-detect либ в `package.json` нет; ровная сетка «по bpm» циклична
   (bpm нет). И снэп только cut-точек без привязки motion к музыке = тот самый сток-шаблон, что мы убиваем.
   → **Бит-синк v2 = фикс-сетка:** взять 1 канонический трендовый mp3, замерить bpm руками ИЛИ захардкодить
   каденс ~0.5с (≈120 BPM, подходит большинству TikTok-аудио) → `quantizeToBeats(blocks, grid)` снапит
   clip.start/length. Дёшево, без новых зависимостей. Настоящий onset-детект — позже, ГЕЙТ: сперва P1.1
   докажет, что может достать реальный mp3-URL. Честно: бит-ровные нарезки сами по себе не делают вирус
   (попадание ревила на долю требует speed-ramp per-clip — вне scope), не выдавать бит-синк за рычаг охвата.

   **DDL (новая миграция `20260621_factory_v2_assembly.sql`):** `ALTER content_assets ADD` asset_type
   (real/ai/utility), role (hook/scene/payoff/transition/text/broll), emotion, duration_sec, beat_suitable,
   tags[] + индексы; новая таблица `factory_assemblies` (edit_json+block_ids+sound_id+beat_times+render_id+
   output_url+otk_score) — хранит РЕЦЕПТ сборки для вариаций (P1.2) и петли winners (P2.1).
   ⚠️ `duration_sec` обязателен для раскладки — бэкфилл при индексации диска (`disk-source`) или ffprobe.

   **Порядок внедрения v2 (отдельная веха ПОСЛЕ ночного C→R→P0→P1→U):** (1) DDL + бэкфилл тегов;
   (2) Assembly Agent (без рендера); (3) `shotstack.ts` + смоук RU-субтитров/watermark; (4) ветка
   assemble→compose-submit→compose-poll; (5) Virlo-биты как audio-трек + фикс-сетка quantizeToBeats.

## РЕШЕНИЕ: монтаж = дефолт финала, одиночная генерация = поставщик блоков
Для ГОТОВОГО публикуемого ролика дефолт — СБОРКА (монтаж), не «одно AI-видео»: один i2v-проход
структурно не даёт удержание (смена кадра 1.5-2с), реальный товар без слопа (интеркат) и звук/субтитры
по битам. Поэтому:
- **Одиночная генерация (fal i2v / Creatify / реальная съёмка) НЕ финал, а ПРОИЗВОДИТ БЛОКИ** → в библиотеку
  (content_assets). Цепочка: генераторы → блоки → Assembly/Shotstack собирает → готовый ролик.
- **Исключения, где одиночный клип = финал (без монтажа):** (1) talking-head UGC (один цельный дубль актёра);
  (2) один уже-идеальный реальный клип; (3) дешёвый тест-рендер (хук-турнир). Для них старая ветка остаётся.
- **Секвенс:** пока библиотека не наполнена/не размечена (Блок 1 + v2.1), Assembly-агенту нечего собирать →
  одиночная генерация (улучшенная P0.1) НАПОЛНЯЕТ библиотеку и тащит нагрузку сейчас; монтаж становится
  дефолтом после Блока 2. Старую single-ветку НЕ удалять — она и поставщик блоков, и путь для 3 исключений.

## Секвенирование (НЕ ломать быстрые победы)
Factory v2 — БОЛЬШЕ одной ночи. Ночной план (C/R/P0/P1/U) — это ФУНДАМЕНТ под v2, а не конкурент:
P0.1 (реальная съёмка = хребет) = тот же mindset библиотеки; R (корпус) = тренд-интеллект сборки;
P1.1 (звук) + P1.2 (вариации) = компоненты сборки. Сначала ночной план (лучше единичные ролики +
наполненная библиотека/корпус), ПОТОМ v2-сборка поверх. Не цементировать монтаж-движок, пока ресёрч
не выбрал его. Assembly Agent + тегирование можно начать сразу после P0/R; монтаж-движок — отдельная веха.
ОТК (P0.3 анти-слоп флор) судит КАЖДУЮ ступень — побеждает та, что даёт лучший hook-rate/удержание.
