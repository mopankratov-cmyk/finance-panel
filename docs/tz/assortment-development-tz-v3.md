Создать в существующей панели модуль, который постоянно находит интересные модели за рубежом, показывает их внешний вид и объясняет, какие признаки популярности уже наблюдаются. Пользователь должен быстро увидеть конкретную вещь, сравнить варианты и выбрать референсы для собственной разработки. Результат работы — визуальная подборка и задание на изучение модели или образца.

Эта версия объединяет ТЗ версии 2.0 и исследование источников от 1 октября 2026 года и является единым действующим ТЗ. Цены, юнит-экономика, котировки поставщиков и расчёты запуска полностью исключены. Основой становятся зарубежные коллекции, Pinterest и публикации о моделях. MPSTATS WB может давать дополнительный российский контекст. Подтверждение на российском рынке не требуется для отбора ранней зарубежной находки.


Состав: требования к модулю и внедрению — разделы 1–13; исходные ссылки — раздел 14; расширенные источники, интеграции и пилоты — разделы 15–22; 17 типов адаптеров — раздел 23; порядок подключения — раздел 24; все 127 записей реестра — раздел 25. Книга Assortment_Trend_Sources.xlsx входит в ТЗ как подробное приложение с фильтрами, статусами, ограничениями и первыми шагами по каждому источнику. Приоритет P0 означает порядок проверки, а не уже работающий доступ.

Изменения версии 3.0: расширен реестр источников; добавлены контракт адаптера, ограничения API, поисковые словари, пилоты и единое стартовое задание для Claude Code. Прежние требования к галерее, доказательствам, инфраструктуре, доступу и этапам сохраняются.

1 Границы модуля и интеграция с панелью

Отдельный пункт главного меню «Разработка ассортимента». Внутри ровно два раздела: «Куртки» и «Сумки». Подборки, источники и карточки открываются внутри этих разделов. Предлагаемые адреса: /assortment-development/jackets и /assortment-development/bags; корневой адрес открывает последний выбранный раздел. Финальные пути проверить по репозиторию.

Существующие /market, /wb/market, /api/market/niches и /api/market/pulse сохраняются. Не создавать второй справочник поставщиков, калькулятор или словарь ролей. Использовать действующие организацию, кабинеты и матрицу из 10 ролей. Не вводить tenant_id/project_id как параллельную систему доступа. Встречавшееся «PVB» означает «по ВБ», отдельной сущности PVB нет.

Направления: куртки NORVIA/HEATON и сумки CLÉRIN. Связи с организациями и кабинетами определить по существующим данным, не угадывать. Категория и бренд служат фильтрами и не заменяют проверку доступа. При необходимости расширить существующий справочник брендов минимальной сущностью направления.

Ozon через MPSTATS запрещён. В этой версии модуль вообще не вызывает Ozon API и не зависит от Ozon. Возможная последующая работа с собственными данными через официальный API Ozon оформляется отдельно после проверки доступа и состава данных. Действующие интеграции Ozon в других разделах панели не отключать.

Не добавлять поля цены, валюты, себестоимости, маржи, СПП, закупочного бюджета или MOQ в модели данных, API, интерфейс, сортировки, рекомендации и экспорт этого модуля. При получении внешней карточки сохранять только разрешённый набор нужных полей. Цены могут быть видны на исходном фото или внешней странице; распознавать и анализировать их не нужно. Отбор не блокируется отсутствием экономических данных.

2 Что пользователь должен получать

Ежедневно — ленту новых моделей с крупными фотографиями, источниками и коротким объяснением интереса. Еженедельно — подборку перспективных силуэтов с конкретными примерами и изменениями за период. В любой момент — поиск по признакам и подбор похожих вещей из уже собранного каталога.

Куртки: демисезонные, ветровки, пуховики, зимние. Предусмотреть сезон и год; исходная рабочая подборка — весна 2027. Осенний всплеск нельзя автоматически объявлять весенней рекомендацией: показывать регион, климатический контекст и обоснование сезонной применимости.

Сумки: ежемесячный черновик пяти новых моделей и резерв. Пять расцветок одной конструкции не считаются пятью моделями. Отбирать разные сочетания силуэта, способа ношения и конструктивных деталей. Если убедительных кандидатов три, показать «3 из 5» и причины. Это план изучения и разработки, а не разрешение на производственную партию.

Для каждой рекомендации нужны фотографии реальных товаров, один или несколько конкретных референсов, ссылки и артикулы при наличии, отличительные детали, основания выбора, неизвестные факты и следующий шаг. Пользователь может принять, отклонить, отложить или запросить образец для изучения. Эти решения улучшают следующие подборки.

3 Источники и порядок подключения

Подключать ограниченную наблюдаемую панель брендов, регионов и запросов с понятным покрытием. Формулировку «анализирует весь интернет» не использовать: интерфейс всегда показывает, что именно отслеживается. Открытая страница подтверждает наличие источника, но не готовность промышленного сборщика.

Полный реестр и типы адаптеров приведены в разделах 23–25. После стартового набора расширять наблюдение на COS, ARKET, Massimo Dutti, H&M, & Other Stories, ASOS и Zalando по результатам пилотов. Это кандидаты подключения, а не готовые интеграции. Женские страницы в списке источников — стартовые примеры; целевую аудиторию каждого направления брать из настроек бренда, мужские куртки не исключать архитектурно.

По каждому источнику вести паспорт: домен, регион, категория, целевая аудитория, способ доступа, разрешённые операции, покрытие, периодичность, последняя успешная загрузка, ограничения хранения медиа, ответственный. Отдельные состояния: проверен автоматический сбор; только ручной ввод; доступ не проверен; временно недоступен; отключён. Публичная доступность не означает разрешение на произвольное копирование; использовать допустимый способ интеграции, не обходить блокировки.

Для готового автоматического MVP требуются минимум два бренда на каждую категорию с реальным обнаружением новых карточек; Zara может входить в обе пары. Если исходный источник недоступен, подобрать доступную замену и явно зафиксировать её. Ручная галерея полезна как промежуточный результат, но не считается завершением автоматического поиска.

4 Как получать данные Pinterest и социальных площадок

Разделить две задачи Pinterest: получение визуальных референсов и измерение интереса к запросам. Пользователь может добавлять пины, доски и изображения вручную. Автоматический поиск изображений подключать только через способ, реально разрешённый и проверенный для приложения. Наличие Trends API не считать разрешением массово собирать любые пины или их скрытые показатели.

Trends API предоставляет растущие запросы, регион и относительную динамику; в документации есть недельный ряд за год. Рейтинг прошлой даты нельзя считать доступным по умолчанию — сохранять собственные снимки. Индексы разных запросов сравнивать только при совместимой нормализации. Связь запроса с конкретной моделью объяснять признаками и помечать как интерпретацию, а не спрос на данный артикул [5].

Официальный Instagram API не считать универсальным поиском любых Reels с полной статистикой. Для автоматизации провести пилот подходящего провайдера на реальных ссылках: проверить доступные просмотры, даты, устойчивость ID, повторное обновление, медиа и ограничения использования. В ТЗ нет обещания, что такой доступ уже оплачен или подключён [7–8].

Для публикации хранить исходную ссылку, автора, время публикации и наблюдения, доступные счётчики и признаки рекламного размещения, если они известны. Отсутствующие просмотры, сохранения и продажи — null с причиной. Пользовательский скриншот разрешён как отдельное доказательство с датой и пометкой ручного ввода.

5 Визуальный интерфейс

В каждом разделе первым экраном открывать адаптивную галерею: 3–5 карточек в ряд на широком экране, крупное фото и минимум текста. Сохранять пропорции изображения; пользователь должен различать силуэт. Не открывать модуль таблицей показателей или диаграммой рынка.

Карточка показывает фото, краткое название модели, бренд, регион, дату обнаружения, метку сигнала и одну фразу «Почему показали». Если модель впервые найдена системой, писать «Впервые у нас», а не «Только что вышла». Возможны быстрые действия: в подборку, сравнить, скрыть, открыть источник.

Представления ленты: «Новинки», «Растёт интерес», «Виральные публикации», «Отмечено ритейлером», «Мои подборки». Это фильтры внутри категории, не отдельные модули. Фильтры также включают период, регион, сезон, подкатегорию, силуэт, детали, источник и статус решения. Сортировки: новые находки, новые подтверждения, свежие изменения; никаких сортировок по цене.

Карточка модели открывает галерею ракурсов, крупные детали, доступные кадры видео, исходные публикации и похожие модели. Ниже — три отдельные группы доказательств: новизна, распространение, сигналы ритейла. Каждое утверждение раскрывается до источника, даты, региона и способа получения. Недоступный ракурс обозначается, а не дорисовывается.

Сравнение 2–6 референсов: фотографии рядом, общие признаки и различия. Подборка тренда: 3–8 примеров из разных источников, выделенные детали, временная шкала и краткий вывод. При меньшем количестве показывать фактическое число. Коллаж строить из реальных изображений с подписями источников. Сгенерированное изображение не является подтверждением существования товара.

6 Описание моделей и поиск похожих

| Категория | Признаки для фильтров и сравнения |
| Куртки | Подтип, длина, объём, посадка плеча, линия низа, воротник, капюшон, застёжка, карманы, рукава, стёжка, видимая фактура, цвет, сочетания деталей |
| Сумки | Силуэт, пропорции, жёсткость формы, способ ношения, ручки и ремень, клапан, застёжка, карманы, фурнитура, фактура, цвет, декор |

Разделять опубликованный факт, визуальную оценку ИИ и ручное подтверждение. По фотографии нельзя достоверно установить натуральность кожи, состав наполнителя, плотность ткани, точные размеры или качество пошива. Для каждого признака хранить источник и уверенность; поддержать «не видно» и ручное исправление. Для видимой фактуры использовать формулировки вроде «замшевый вид» до подтверждения состава.

Идентичный товар связывать по надёжному артикулу бренда или другому проверяемому идентификатору. Модель, цветовой вариант, региональная карточка и публикация — разные сущности или связанные записи. Визуальное сходство формирует связь «похожая модель», а не доказательство общего производителя. Кластер силуэта объединяет похожие модели разных брендов и допускает ручное разделение.

Первый поиск похожих работает по признакам, тексту и визуальным отпечаткам изображений для дублей. Перцептивный хеш не объявлять полноценным семантическим поиском силуэтов. Поиск по загруженной фотографии использует те же извлечённые признаки; более точный поиск через эмбеддинги подключать после проверки инфраструктуры. Наличие pgvector не предполагать.

7 Как объяснять популярность

Не вводить единый «балл гарантированного успеха» или вероятность продаж без проверенной модели. Пользователь видит отдельные факты и объяснение рекомендации. Раннюю необычную модель можно показывать даже с единственным источником, с пометкой «Пока одна находка».

Новизна: первое наблюдение системой, отметка New на сайте, появление новой вариации силуэта. Дату выхода указывать только при наличии опубликованного подтверждения. Первая загрузка каталога создаёт исходную базу и не объявляет все старые модели новинками.

Распространение: независимые публикации, динамика их счётчиков, появление похожих деталей у нескольких брендов и рост соответствующих запросов. Перепосты одного ролика не считать независимыми находками; магазины одной группы показывать отдельно от полностью независимых подтверждений. Один вирусный ролик — сигнал к просмотру, а не доказательство устойчивого спроса.

Ритейл: публичная отметка бестселлера, позиция в конкретном рейтинге, повторное появление коллекционной модели, наблюдаемые изменения наличия. Официальная отметка магазина остаётся утверждением магазина. Исчезновение размера может быть связано с поставкой или малым остатком; оно не превращается в число продаж. Количественные продажи допустимы лишь при прямом источнике с периодом и объяснением охвата.

Рост счётчика рассчитывать только при двух сопоставимых наблюдениях: разница значений и времени. Отрицательную разницу помечать как коррекцию, а не падение спроса. Без временной базы не писать «быстро растёт». Если доступен фон по автору, сравнивать ролики одинакового возраста; если нет — показывать абсолютные наблюдения без выдуманного процентиля. Просмотры разных платформ не суммировать в единую аудиторию.

Метка «Есть подтверждения из разных каналов» требует минимум двух семейств источников и подтверждённой связи с моделью либо её кластером. Ритейл и Pinterest по широкому запросу не доказывают популярность конкретного артикула. Число независимых свидетельств, давность, пробелы и полнота наблюдения показываются отдельно; изменение состава наблюдаемых сайтов не выдаётся за рост тренда.

8 Подборки и задание на разработку

Рекомендация включает: рабочее название идеи; главное фото; конкретные референсы; 1–3 отличительные детали; что сейчас наблюдается; подходит ли направление целевому сезону и аудитории; какие факты отсутствуют; следующий шаг. У каждого фактического утверждения есть evidence_id, у предложения по собственной модели — пометка «Идея разработки».

Подборка пяти сумок содержит пять разных конструктивных идей и до трёх резервных. Пользователь может заменить кандидата и указать причину: повторяет ассортимент, не нравится форма, неподходящая аудитория, слабые подтверждения. Для курток готовится сезонная доска с группировкой по подтипу и силуэту, без обязательного количества моделей.

Статусы: новая находка, наблюдаем, в подборке, выбрана для разработки, нужен образец, отклонена, архив. Выбор для разработки — решение человека. ИИ предлагает, но не размещает заказ. Экспорт формируется из сохранённой версии подбора и содержит фото, ссылки, артикулы, детали для изучения, предлагаемые отличия собственной модели, вопросы к образцу и ответственного.

Задание предназначено для изучения конструкции и дальнейшей работы дизайнера и конструктора. Не обещать выпуск готовых лекал из фото. После получения физического образца можно приложить собственные фотографии и замечания. Закупки, котировки и производственный заказ при необходимости открываются в уже существующих разделах панели; внутри этого модуля их не реализовывать.

9 Данные и внутренний API

Минимальная логическая модель: источник и его паспорт; референс товара; медиа; публикация или наблюдение; доказательство; кластер похожих моделей; подборка с кандидатами; решение и версия задания. Задания сборщика и журнал действий переиспользовать из действующей инфраструктуры, если подходят. Логические объекты не требуют отдельной таблицы для каждого названия.

Ключ референса: источник, регион и source_item_id; при отсутствии ID — нормализованный URL. Сохранять first_seen_at, published_at при наличии, observed_at и collected_at отдельно. Доказательство хранит значение либо null, единицу, период, регион, URL, способ получения и снимок разрешённых полей. Пустая строка, ноль и отсутствие данных не взаимозаменяемы.

История наблюдений дополняется, а не перезаписывается. Повторная загрузка не создаёт дубль. Связь публикации с конкретным товаром хранит способ установления и уверенность. Кластер хранит состав и версию; изменение состава не переписывает старое решение. Медиа имеют происхождение, контрольную сумму, права доступа и правила удаления.

API разместить под свободным префиксом /api/assortment-development. Нужны операции: список и фильтрация референсов; импорт URL или файла; похожие модели; наблюдения и доказательства; управление подборками; решения; экспорт задания; состояние источников и фоновых задач. Названия согласовать с принятым стилем репозитория. Все чтения, файлы и экспорты проверяют действующий организационный доступ на сервере.

Импорт принимает категорию, разрешённое направление, URL или файл, заметку и idempotency_key. Возвращает reference_id и при необходимости job_id. Источник без доступа возвращает понятный статус и возможность прикрепить фото, а не выдуманный разбор страницы. Изменение решения использует проверку версии для защиты от одновременной правки.

10 Сборщик и обработка изображений

Учитывать действующие ограничения: Vercel до 300 секунд, готовой очереди и pgvector нет. Веб-приложение отдаёт интерфейс и короткие API-запросы. Планирование сбора, обработка изображений и видео работают вне веб-запроса. Предпочтительно использовать существующий mini после проверки ресурсов и устройства текущих задач полок и выплат.

На этапе 0 выбрать механизм задач. Если переиспользовать нечего, достаточно таблицы заданий с атомарным захватом, lease_until, heartbeat, attempts, next_run_at и состояниями queued/running/succeeded/failed. Просроченную аренду можно повторить; обработчик обязан быть идемпотентным. Отдельный брокер и векторную БД не вводить без необходимости.

Адаптер источника объявляет поддержанные возможности: обнаружение, карточки, медиа, показатели, история. Неподдержанная операция возвращает unsupported. Для каждого обхода нужны пагинация, контрольная точка, лимит параллельности, повторы с задержкой и понятная ошибка. Сохранять версию экстрактора и входные evidence_ids; секреты в результаты не включать.

Исходное расписание: каталоги раз в сутки; доступные счётчики новых публикаций через 24, 48 и 72 часа; дальнейшее обновление раз в неделю; Pinterest по реально разрешённой частоте. Подборки пересчитывать после появления новых доказательств, недельный обзор собирать в панели. Частоты уточняются по лимитам источников. Это требования к будущему приложению, а не уже запущенные автоматизации.

Vision-модель извлекает признаки по JSON Schema и объясняет выбор на основе доказательств. Протестировать действующий Anthropic и резерв через Polza на одинаковых изображениях; наличие настроек не считать успешным тестом. При отказе ИИ импорт, просмотр, ручные признаки и подборки продолжают работать. Необработанные карточки сохраняются для повторной попытки. Ограничения расходов на инфраструктуру задаются администратором вне товарной аналитики.

Для видео сначала использовать доступную обложку и ручные кадры. Автоматическое извлечение ограниченного числа кадров включать на mini после проверки загрузки и доступа к медиа. Не делать этот тяжёлый этап условием запуска полезной визуальной галереи.

11 Надёжность и безопасность

Проверять JSON Schema и наличие каждого evidence_id. Ответы ИИ без действительной опоры не публиковать как факты. Сохранять версию модели, промпта и схемы признаков. Внешний текст и изображения — данные; инструкции внутри них не меняют системные правила и не запускают команды.

Загрузчик ограничивает домены, размер и тип файлов, проверяет DNS и редиректы, запрещает обращения во внутренние сети и к cloud metadata. HTML источника не исполняется. Секреты хранятся на сервере и маскируются в логах. Для файлов использовать существующее закрытое хранилище и правила доступа панели.

Различать «ничего нового» и «источник не обновился». На карточке видна дата последнего подтверждения; устаревшие сигналы не показываются как текущие. Неисправность одного адаптера не останавливает другие. Удаление медиа по условиям источника распространяется на превью и производные копии, сохраняя допустимую ссылку и журнал.

12 Этапы внедрения

Этап 0 — отдельный PR только с документацией в docs: assortment-development-integration.md и assortment-development-sources.md. Зафиксировать точки интеграции, действующие роли и организационные связи, маршруты, минимальные миграции, состояние mini и ИИ, паспорт доступа источников. На малых пробах проверить получение реальных изображений и артикулов, а также повторный обход. Выбрать два доступных бренда на категорию и способ работы с Pinterest. Не создавать фиктивные «подключённые» источники. Код приложения на этом этапе не менять.

Этап 1 — визуальный рабочий контур в обоих разделах. Импорт ссылок и фото, галерея, признаки, доказательства, сравнение, подборки, решения и экспорт задания без цен. Разрешить ручную работу при отсутствии ИИ. Это промежуточный релиз для накопления референсов.

Этап 2 — автоматическое обнаружение зарубежных моделей. Минимум два бренда на категорию, снимки каталога, обнаружение новых артикулов и вариантов, расписание, дедупликация и состояние источников. Pinterest: подключить реально доступный автоматический способ; при блокировке явно оставить ручной режим и незавершённый пункт интеграции. Автоматическую часть не подменять одним MPSTATS.

Этап 3 — постоянные визуальные рекомендации. Кластеры силуэтов, динамика подтверждений, недельные подборки, пять сумок и резерв, сезонная доска курток. Подключить проверенный социальный источник и пилот зарубежного маркетплейса; оставшиеся ограничения отразить в интерфейсе. Автоматизация Instagram не считается работающей по факту существования кнопки.

Каждый этап — отдельный PR с демонстрацией реальных данных и перечнем ограничений, следующий этап после согласования предыдущего. Миграции подготовить для ручного применения владельцем. Оценку сроков давать после этапа 0. EDITED, WGSN и Heuritech не делать обязательными зависимостями; их возможный вклад проверять позже на собственных задачах.

13 Приёмка

Проверки выполнять на реальных разрешённых данных; аварии и граничные случаи — на явно обозначенных фикстурах. Достаточный стартовый набор: по 30 референсов каждой категории из нескольких источников, включая разные ракурсы, похожие модели и цветовые варианты. Это демонстрационный набор, не доказательство точности на всём рынке.

| Сценарий | Ожидаемое поведение |
| Открытие модуля | Видны «Куртки» и «Сумки», первым экраном фотографии, раздел «Рынок» работает как раньше |
| Сквозной отбор | Из найденной модели пользователь открывает источник, сравнивает детали, принимает решение и экспортирует визуальное задание |
| Проверка границ | Нет ценовых полей и экономических расчётов; модуль не вызывает Ozon и MPSTATS Ozon |
| Автоматический обход | Подключены два бренда на категорию; повторный запуск сохраняет историю и не дублирует модели; появление нового объекта проверено отдельно |
| Ранний зарубежный референс | Доступен для отбора без MPSTATS и российских аналогов |
| Большой охват ролика | Показан факт охвата с датой; нет вымышленных продаж или обещания успешного запуска |
| Широкий тренд Pinterest | Связан с признаками кластера, не объявлен спросом на конкретный артикул |
| Нет материала или ракурса | «Неизвестно» или «не видно»; состав, размеры и изображения не выдуманы |
| Дубли и похожие вещи | Перепосты и расцветки не умножают число независимых подтверждений и новых моделей |
| План сумок | Пять разных конструктивных идей либо честный неполный план с причинами |
| Сбой доступа или ИИ | Видимое ограничение; ручная работа и остальные источники доступны |
| Чужая организация или вредоносный URL | Сервер запрещает доступ или безопасно останавливает импорт |

Отдельно вручную проверить не менее 30 предложенных связей «похожая модель», включая сложные отрицательные пары. Автоматические связи идентичности по одному сходству изображения запрещены. Неверные признаки исправляются без потери исходного предположения ИИ. Проверить работу после перезапуска сборщика и организационные ограничения для медиа и экспортов.

Продуктовый результат оценивать по времени до полезной находки, доле выбранных пользователем референсов, разнообразию идей и числу исправлений. Система должна помогать увидеть и понять модель. Рост продаж и прибыль не являются метриками приёмки этой версии.

15 Расширенная карта источников

В приложенной книге Assortment_Trend_Sources.xlsx собраны конкретные сайты, платформы и поставщики данных. Для каждой записи указаны категория, регион, полезные данные, приоритет, способ подключения, ограничения, статус проверки и первый шаг. «Страница проверена» означает просмотр публичной страницы при исследовании; это не тест промышленного сборщика. «Документация проверена» не означает наличие рабочего ключа у пользователя. Непроверенные кандидаты отмечены отдельно.

Реестр охватывает основные классы источников, но не является обещанием собрать весь интернет. Список расширяется из находок: новый бренд, автор или магазин добавляется с источником рекомендации и проходит пилот. Поставщик данных не считается новым независимым подтверждением, если он пересказывает уже учтённую карточку или публикацию.

Зарубежные бренды. Новые коллекции и конкретные модели Zara, Mango, Uniqlo, COS, Massimo Dutti и других марок. Для курток отдельно наблюдать производителей верхней одежды; для сумок — специализированные бренды. Каталог даёт фотографии и артикул, а не доказательство продаж.

Азия. MUSINSA, 29CM и W Concept показывают корейские модели; ZOZOTOWN, Rakuten, GU и WEAR добавляют японский контекст. Xiaohongshu и Douyin — отдельный китайский слой. Сначала фиксировать конкретный регион и аудиторию: global-витрина может отличаться от внутреннего рынка.

Социальные публикации и образы. Pinterest, Instagram, TikTok, YouTube, WEAR, StyleHint, LTK и профильные сообщества помогают увидеть, как вещь выглядит в жизни, с чем её носят и какие детали обсуждают. Охват и комментарии измеряют интерес к публикации. Сохранения и продажи, которых источник не отдаёт, не подставлять.

Поисковый интерес. Google Trends, Pinterest Trends, NAVER DataLab, Baidu Index и при необходимости Wordstat помогают проверить названия силуэтов и сезонность. Поиск по теме «сумка полумесяц» не доказывает спрос на конкретный артикул.

Подиумы и редакции. Tagwalk и Vogue Runway дают ранние коллекционные формы; PurseBlog, Who What Wear, WWD, NOWFASHION и другие издания — конкретные примеры и редакционный контекст. Редакционные подборки могут быть коммерчески мотивированы. Не складывать одинаковые пресс-релизы как независимые подтверждения.

Профессиональная аналитика. EDITED, Heuritech, WGSN, Future Snoops, Trendalytics, Trendstop, Stylumia и POP Fashion могут ускорить поиск. Для системы ценны покрытие нужных категорий, доступ к изображениям, возможность выгрузки и объяснимая методика. Не закупать все подписки без сравнения тестовых выборок.

Фабрики и материалы. 1688, Alibaba, Made-in-China и Global Sources показывают предложение. LINEAPELLE, Première Vision, APLF и PERFORMANCE DAYS помогают находить материалы, отделку и фурнитуру. Дополнительно принимать собственные фото из шоурумов, каталоги поставщиков, разрешённые lookbook-файлы и заметки закупщика. Этот слой помогает реализовать выбранную идею.

Вторичный рынок. Vestiaire Collective, The RealReal, Depop и Vinted полезны для возвращающихся силуэтов и архивных моделей. Число объявлений и снятие карточки с публикации не равны спросу и подтверждённой продаже.

Дополнительные каналы для последующего пилота: официальные сайты недель моды, каталоги участников выставок, рассылки брендов, Weibo, Bilibili, публичные fashion-материалы WeChat, Meta Ad Library и Google Ads Transparency Center. Их доступ и охват пока не проверены. Рекламный креатив отражает продвижение модели, а не органическую виральность. Закрытые сообщества и личные сообщения не собирать без соответствующего доступа и разрешения.

18 Общий контракт источника

В source registry хранить:
source_id, original_source, provider_id, name, source_family, domain, locale, country, audience, categories, adapter_type, access_status, capabilities, credentials_ref, seed_urls, seed_queries, allowed_fields, media_policy, refresh_schedule, last_success_at, parser_version.

capabilities должны отдельно описывать discovery, item_details, images, videos, public_metrics, historical_metrics и export. Значения: supported / unsupported / untested. Возможность получить фото одной карточки не означает способность обнаруживать новые карточки всего каталога.

Каждая запись содержит исходный source_item_id или стабильный URL, опубликованную дату при наличии, first_seen_at, observed_at, collected_at, регион, медиа и доказательства. Для числового факта: значение, единица, период, география, метод получения и статус observed / retailer_claim / provider_estimate / forecast / manual. Для недоступного факта — null и причина.

Данные адаптера разделить на три вида:
1) product_reference — конкретная модель, изображения, варианты, артикул;
2) publication — пост или ролик, автор, дата, доступные счётчики;
3) trend_observation — динамика запроса, признака или рейтинга.

ИИ связывает их через признаки, но не подменяет один вид другим. Широкий поисковый тренд относится к кластеру. Exact match требует надёжного идентификатора или подтверждения человеком. Показы, пины, фиды и карточки одной вещи не считать независимыми моделями.

Публичный статус источника, статус доступа к API и возможности адаптера — разные поля. «Документация проверена» относится к исследованию; supported для конкретного подключения выставляется только после успешной пробы. Внутренний source registry использует стабильные ID S001–S127 из приложения; provider_id не подменяет original_source. Новые записи получают новые ID, существующие не перенумеровывать.

19 Порядок обработки данных

Шаг 1. Discovery. Получить новые URL/ID из выбранной категории, фида, поискового запроса или списка авторов. Первая загрузка формирует базу сравнения и не объявляет весь каталог новинками.

Шаг 2. Fetch и проверка. Получить разрешённые поля, изображения и метаданные. Проверить типы, домен, регион и права хранения. Цены и экономические поля удалить на границе адаптера.

Шаг 3. Нормализация и дедупликация. Отделить модель от расцветки и региональной карточки. Сохранить первоисточник даже при получении через EDITED, FastMoss или другой сервис. Перцептивные хеши использовать для копий фото; одинаковый силуэт не является доказательством идентичности.

Шаг 4. Визуальные признаки. Куртки: подтип, длина, объём, плечо, воротник, карманы, застёжка, рукав, низ, капюшон, стёжка. Сумки: силуэт, пропорции, жёсткость формы, ручки, ремень, клапан, застёжка, фурнитура, фактура. Состав материала и размеры не угадывать по фото.

Шаг 5. Кластер и доказательства. Сопоставить похожие конструкции, независимые бренды, публикации и запросы. Раздельно показывать новизну, распространение, ритейл-сигналы и прогнозы. При одной находке оставить её доступной с честной пометкой.

Шаг 6. Рекомендация. Показать реальные изображения и коротко объяснить: какая деталь интересна, где встречается, какие подтверждения появились, что пока неизвестно, какой образец стоит изучить. Сохранить выбранную пользователем модель в сезонную или месячную доску.

Добавить азиатскую доску WEAR/29CM/MUSINSA и ручные находки Xiaohongshu. Проверить Pinterest Trends, Google Trends и YouTube API. После этого испытать один социальный сборщик и FastMoss, затем Rakuten и подиумные источники. Профессиональный агрегатор подключать после сравнения с уже работающей базой.

22 Пилот и приёмка интеграций

Для одного кандидата: проверить 20 реальных карточек или публикаций, обе категории где применимо, повторное обновление, несколько регионов при заявленном покрытии и частичный сбой. Зафиксировать фактические поля, недоступные значения, права на изображения и поддержанный способ обнаружения новинок.

Для визуального поиска: взять 20 фото, проверить похожие модели и ошибки совпадения. Для API трендов: сравнить одинаковый период, регион и нормализацию с исходным интерфейсом. Для provider-estimates: запросить методику; если она не раскрыта, оставить явную подпись об оценке.

Критерии готовности: источник действительно приносит новые изображения моделей; результат имеет первоисточник и дату; повторный запуск сохраняет историю без дублей; отказ одного источника не останавливает остальные; в модуль не попадают цены и вызовы Ozon; изображения и экспорт защищены действующими правами организации.

Сборщик и тяжёлые задачи выполняются на mini после проверки ресурсов. Vercel обслуживает короткие API-запросы и интерфейс. Для ИИ сохраняется работа без провайдера: ручные признаки, просмотр и подборки доступны даже при отказе Anthropic или резерва через Polza.

23 Типы адаптеров

Реализовать общие контракты и конфигурации источников. Наличие 127 записей не требует 127 отдельных подсистем. C1–C7 и A1–A10 описывают способы работы; unsupported и untested — допустимые результаты пилота.

23.1 C1 Каталоги — Каталог бренда или магазина

Доступ: Сначала лицензионный набор/фид; затем допустимый HTML-сбор.

Реализация: Определить locale, категории, source ID, галерею. Sitemap — только подсказка, если доступен. Парсить JSON-LD/HTML при разрешённом доступе.

Обновление: Снимок раз в сутки; курсор; история first_seen; не выдавать первую загрузку за новинки.

Ограничения: Нет гарантированного общего API Zara, COS и других брендов. При блокировке — ручной импорт или замена.

Проверка: Пилот 20 карточек и второго обхода. Фото + исходный артикул/URL + дата обязательны.

23.2 C2 Social — Публикации и образы

Доступ: Разрешённый официальный API, коммерческий поставщик или ручной импорт.

Реализация: Список авторов/запросов; URL, автор, published_at, observed_at, доступные счётчики и связь с вещью.

Обновление: Повторить счётчики через 24/48/72 часа; кластеризовать перепосты.

Ограничения: Чужие скрытые insights не получать. Публичные счётчики не доказывают продажи.

Проверка: 20 публикаций, включая удалённую и недоступную; два наблюдения; разные типы авторов.

23.3 C3 Редакционные — Показы, медиа, выставки

Доступ: RSS при наличии, договорной экспорт, ссылки, разрешённые PDF и фото.

Реализация: Хранить сезон, коллекцию, look number, описание детали и страницу источника.

Обновление: Обход по выпуску коллекции/отчёта; публикации по доступному RSS.

Ограничения: Право читать подписку не обязательно разрешает массовое копирование изображений.

Проверка: 10 материалов; точная ссылка на каждый референс; фильтры куртки/сумки/сезон.

23.4 C4 Китай — Китайские площадки и закупщик

Доступ: Официальный доступ по реальным полномочиям либо договорной провайдер.

Реализация: Начать с добавления URL/фото закупщиком; словарь китайских терминов проверяет человек.

Обновление: Следить за списками продавцов и запросами, а не пытаться выгрузить всю площадку.

Ограничения: Seller API может ограничиваться своим магазином. Не обходить CAPTCHA, login или технические ограничения.

Проверка: Проверить 20 объектов и право на их использование; отдельно описать найденные и недоступные поля.

23.5 C5 Лицензия — Платная аналитика и отчёты

Доступ: Demo, API/export entitlement, разрешение на внутреннее использование.

Реализация: Запросить схему, реальный sample, страны, подкатегории, гранулярность SKU/силуэт и image rights.

Обновление: Частота определяется договором и фактическим обновлением.

Ограничения: Не покупать все сервисы сразу. Прогнозы и оценки явно подписывать.

Проверка: Одна и та же тестовая подборка для сравнения поставщиков; новые полезные находки важнее размера базы.

23.6 C6 Сборщик — Apify или собственный worker

Доступ: API запуска задач и чтения dataset / собственная задача mini.

Реализация: Сохранять actor/version/input; проверять выходную схему и источник каждой записи.

Обновление: Асинхронный запуск, polling/webhook, retries, idempotency, лимиты.

Ограничения: Провайдер не делает сбор разрешённым автоматически. Actor может перестать работать.

Проверка: Перезапуск без дублей, частичный сбой и изменение структуры страницы.

23.7 C7 Фиды — Awin и прямые фиды брендов

Доступ: Договорной CSV/XML/JSON по HTTPS или SFTP.

Реализация: Получить разрешённый feed URL и обновления; импортировать изображения, название, ID, категорию и ссылку.

Обновление: Проверять timestamp/hash; забирать только изменённый фид.

Ограничения: Отбрасывать цены на входе; не считать партнёрский доступ универсальной лицензией.

Проверка: 20 карточек совпадают с магазином; обновление сохраняет историю; недоступные изображения отмечены.

23.8 A1 Pinterest — Pinterest Trends API

Доступ: OAuth и соответствующий доступ приложения.

Реализация: Документирован пример GET /v5/trends/keywords/{region}/top/growing. Параметры проверить по текущей схеме.

Обновление: Снимки рейтингов + недельные ряды; сохранять вариант нормализации.

Ограничения: API ключевых слов не заменяет поиск пинов. Индексы разных запросов могут быть несопоставимы.

Проверка: Два запроса по сумкам и курткам, два региона; нулевой интерес отличается от недоступных данных.

23.9 A2 YouTube — YouTube Data API

Доступ: API-проект; ключ для доступных публичных операций, OAuth где требуется.

Реализация: search.list → IDs; videos.list(part=snippet,statistics) → наблюдения.

Обновление: Обновлять известные video IDs; квоты читать из актуального проекта.

Ограничения: Не скачивать видео через несуществующий Data API endpoint; использовать embed/разрешённые материалы.

Проверка: Поиск на двух языках; недоступный ролик; отсутствующий счётчик.

23.10 A3 Rakuten — Rakuten Ichiba Ranking API

Доступ: Application ID и актуальные требования Rakuten.

Реализация: Выбрать genreId и актуальную версию Ranking; получить rank, URL и разрешённые изображения.

Обновление: Сохранять снимок рейтинга по категории и дате.

Ограничения: Порядковое место не является количеством продаж. Условия использования изображений проверить.

Проверка: Обе категории, переход страниц, повторное наблюдение того же itemCode.

23.11 A4 eBay — eBay Browse API

Доступ: OAuth application token; проверить production eligibility.

Реализация: Keyword/category search и search_by_image; затем item details.

Обновление: Обновлять только выбранные модели.

23.12 A5 Trends — Google Trends и провайдеры

Доступ: Официальная alpha по допуску; иначе CSV или DataForSEO.

Реализация: Хранить provider, keywords, geo, timeframe, search property и шкалу.

Обновление: Не смешивать веб-поиск, Shopping и YouTube Search; сравнивать при совместимой нормализации.

Ограничения: Избегать обязательной зависимости от неофициальной библиотеки, выдаваемой за официальный API.

Обновление: Категория, период, устройство и демография хранятся отдельно.

Ограничения: Не путать актуальный HUB со старыми Search Shopping API и старыми ключами.

Ограничения: Не считать чужие заявления об accuracy проверенными; не импортировать цены.

Ограничения: Показатели провайдера считать оценками до проверки методики; не переносить их на весь мир.

Проверка: 20 товаров с видео; проверить карточки, атрибуцию, свежесть и доступность истории.
