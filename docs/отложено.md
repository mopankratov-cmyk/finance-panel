# Отложено — что нельзя сделать официальным WB API

Функции Inferno, которые требуют возможностей вне официального API Wildberries (их бэкенд использует скрейпинг кабинета и/или сторонние интеграции). Реализованы частично или отложены — без выдумывания.

## 1. Истинный A/B-замер CTR по вариантам обложек
**Что у Inferno:** показывают, какая обложка реально набрала больше CTR.
**Ограничение:** официальный API не даёт per-variant атрибуцию кликов. Чтобы измерить, нужно по очереди ставить каждую обложку главным фото карточки (WB Content API `/content/v3/media/save` это умеет) и мерить CTR воронки в окне показа — это контролируемый раскат во времени, а не мгновенный A/B.
**Что сделано у нас:** генерация/хранение вариантов обложек (Higgsfield), выбор победителя вручную, анализ текущего рекламного CTR/CPC/CPM по SKU + эвристическая рекомендация CPM. 
**Чтобы добить:** добавить смену главного фото через Content API + планировщик окон показа и сравнение CTR воронки до/после (как в модуле «Дизайн-эффекты»).

## 2. Сохранение креативов в Google Drive
**Что у Inferno:** `save-to-drive`, `gfolder-validate` — выгрузка фото/видео в гугл-папки.
**Ограничение:** нужен Google Drive API + OAuth-согласие пользователя (вне WB).
**Что сделано у нас:** прямое скачивание/ссылка на результат (CDN Higgsfield).
**Чтобы добить:** подключить Google OAuth + Drive API (отдельная интеграция).

## 3. WMS-заказ / МойСклад + раскладка по «готовой таре»
**Что у Inferno:** `createWmsOrder` — создание заказа в складской системе; загрузка «готовой тары» (containerscontent.xlsx) и раскладка целыми коробами по складам; проверка ограничений WB по коробам (`check-restrictions`); healthcheck конвейера.
**Ограничение:** это интеграция с МойСклад (WMS) + ручная загрузка тары + скрейп ограничений WB — вне WB API.
**Что сделано у нас:** вкладка «Поставки» рендерит целевые склады с долями (%) по фактическому остатку `wb_stocks`, мин. партию, сводку «Итого». Расчёт потребности к поставке (need30/45/60, дни до нуля) живёт в React-модуле «Закупки» (`/supplies`). Эндпоинт `wms-ready` отдаёт `{cookie:false}` — раскладка по таре пустая, пока не загружена тара.
**Чтобы добить:** подключить API МойСклад (ключи) + парсер containerscontent.xlsx + скрейп ограничений WB. Сами действия (`percentages`, `export`, `wms-create`, `wb-supply-num`, `reset`, `healthcheck`, `check-restrictions`, `exclude-*`, `uploadTara`, `uploadWbStock`) — отложены.

## 4. Часть рекламной аналитики «как в кабинете»
Некоторые срезы (ставки конкурентов, аукцион в реальном времени, поисковая выдача по запросу) Inferno берёт скрейпингом кабинета. Официальный API даёт рекомендованные ставки (`/api/advert/v0/bids/recommendations`) и статистику — этого хватает на ~90%. Реал-тайм аукцион — отложено.

## 6. SEO — ✅ СДЕЛАНО (после добавления content-токена)
Реализовано: чтение title/description карточек (Content API `content/v2/get/cards/list`), AI-улучшение текста (Claude) + применение на WB (`content/v2/cards/update` с сохранением остальных полей карточки). Модуль `/analytics/seo`.
**Частично отложено:** детальная статистика поисковых кластеров/частотностей (`/adv/v1/normquery/stats` вернул пусто, форма не подтверждена; позиции выдачи Inferno берёт скрейпингом — вне API).
**Раскрытие SKU «поисковые запросы»** (`/api/seo/keywords/{nm}`): ✅ РЕАЛИЗОВАНО через WB Seller-Analytics `POST /api/v2/search-report/product/search-texts` (токен WB_STATS_TOKEN). Отдаёт реальные запросы + частотность WB (`frequency.current`) + медианную позицию (`medianPosition.current`) с цветовой подсветкой. **Частично отложено:** позиция по ДНЯМ (посуточный heatmap у Юры) — официальный API даёт позицию агрегатом за период, посуточное требует ежедневного парсинга выдачи (вне API). Показываем одну колонку «медианная позиция за 14 дней».

## 7. Склейки — ✅ СДЕЛАНО
Реализовано: чтение группировки карточек по imtID (Content API). Модуль `/analytics/sklejki` показывает склейки (вариации одного товара). Изменение состава склеек через API ограничено WB (часто только в кабинете) — read-only.

## ⚠️ Управление рекламой требует WRITE-токена
Текущий `WB_TOKEN_ADVERT` — **read-only** (WB на запись отвечает `401 "read-only token scope not allowed"`). Поэтому старт/пауза/стоп/пополнение/изменение ставок **построены и защищены**, но при выполнении дают 401. Нужен токен «Продвижение» с правом управления (не read-only). Тогда заработают все write-операции, включая изменение ставок (с защитой ×2 и журналом `advert_bid_changes`).

## Перенесено в отложено (по запросу, низкий приоритет):
- **CTR-тест: загрузка своей картинки / из URL конкурента** — не делал (есть «из карточки» и «генерация»).
- **Несколько рекламных кабинетов** (`advSwitchCabinet`) — один кабинет/токен.
- **История пополнений + Optima-оптимизация** — показываю только баланс.
- **Видео-сториборды (мульти-сцена с правками)** — одиночное image-to-video.

## 9. Экспорт «Новые цены» XLSX (Воронка, кнопки ±5/10%) — ✅ СДЕЛАНО (2026-06-17)
Реализовано: текущая каталожная цена из офиц. **Discounts-Prices API** (`GET /api/v2/list/goods/filter`, по токену кабинета SKU — привязка по `cabinet_id` из БД), пересчёт ±5/10%, генерация .xlsx **своей мини-писалкой без зависимостей** (`lib/xlsx/write.ts`: OOXML + STORE-zip + CRC32). `/api/design/price-update` отдаёт файл + заголовки `X-Price-Found`/`X-Price-Missing` (как ждёт UI). Колонки: nmID · артикул продавца · кабинет · текущая цена · новая цена · скидка.
**Частично отложено:** прямое ПРИМЕНЕНИЕ цен через API (`POST /api/v2/upload/task`) — намеренно не делаем (живая правка цен; отдаём файл для ручной загрузки/сверки). Если у токена нет скоупа «Цены и скидки» — роут отдаёт понятную 403 (перевыпустить токен).

## 8. Видео-сториборды (мульти-сцена)
**Что у Inferno:** `video-storyboard` — раскадровка из нескольких сцен с правками.
**Что сделано у нас:** одиночное image-to-video (Higgsfield DoP) из фото карточки.
**Чтобы добить:** цепочка сцен + склейка (несколько генераций + монтаж) — возможно через Higgsfield, но это отдельный объёмный блок.
