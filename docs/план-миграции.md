# План миграции: finance-panel → функционал infernoff.ru

> Сравнение моего проекта с inferno. Вся реальная функциональность inferno = модуль `/wb/` (остальное — заглушки/мокапы). Мой финансовый блок — преимущество, **не трогаем**.

---

## 0. Что у меня уже есть (карта проекта)

**Финансы (моё преимущество — у них «скоро»):** `/calendar` (ДДС), `/payments`, `/accounts`, `/loans`, `/opiu` (ОПиУ).
**WB-аналитика:** `/analytics/rnp` (РНП + реальный ДРР), `/analytics/funnel` (воронка+бенчмарки), `/analytics/sales`, `/analytics/ads` (реклама — read-only), `/analytics/products`, `/analytics/warehouse`.
**Юнит/закупки:** `/unit`, `/supplies`.
**Система:** `/sync` (синки+журнал), `/agent` (AI-агент), `/content` (текст карточек + фото Higgsfield, в т.ч. image-to-image).
**Синки в Supabase:** orders, sales, stocks, adverts, advert-stats, funnel.

## 2. ЕСТЬ У МЕНЯ, НЕТ У НИХ — оставить / удалить

| Моё | Решение |
|-----|---------|
| **Финансы** (`/calendar`, `/payments`, `/accounts`, `/loans`, `/opiu`) | ✅ **ОСТАВИТЬ** — моё ключевое преимущество (у них «скоро») |
| `/analytics/sales` | ⚠️ дублирует РНП, на старом direct-API → **кандидат на удаление** (перенести нужное в РНП) |
| `/analytics/products` | ⚠️ старая страница товаров → **кандидат на удаление** |
| `/analytics/warehouse` | ⚠️ дублирует `/supplies` → **кандидат на удаление** |
| `/api/wb/*` (data, orders, sales, stocks, ads, ads-stat) | ⚠️ старый прямой WB-API (`useWbData`), заменён синками в Supabase → **кандидат на удаление** (кроме того, что ещё использует `/analytics/ads`) |
| `lib/wb/loadData.ts`, `hooks/useWbData.ts` | ⚠️ старый слой данных → удалить вместе с `/api/wb/*` и старыми страницами |
| `/agent`, `/content`, `/sync` | ✅ оставить — это и есть аналоги их lab/agent, лучше интегрированы |

> ⚠️ Удаление `/analytics/sales|products|warehouse` и `/api/wb/*` затронет старую страницу `/analytics/ads`, которая ещё работает на `useWbData`. Перед удалением — перевести `/analytics/ads` на синканные таблицы (или удалить в пользу нового модуля «Реклама»).

## Предлагаемый порядок реализации (Этап 3)

1. **Чистка** (после твоего ОК): удалить `/analytics/sales|products|warehouse`, `/api/wb/*`, `useWbData`/`loadData` — предварительно сняв зависимость `/analytics/ads`.
2. **Управление рекламой** — старт/пауза/ставки/пополнение/массовые (официальный Advert API).
3. **Дизайн/эффекты + Планирование + Roadmap** — свои таблицы Supabase + страницы.
4. **CTR-тесты** — таблица + страница + генерация обложек (Higgsfield).
5. **SEO + Склейки** — в объёме доступного WB API.
6. **Контент-видео** — Higgsfield video в `/content`.
7. Что невозможно официальным API (Google Drive, скрейпинг) → `docs/отложено.md`.
