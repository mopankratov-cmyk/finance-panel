# Marketplace payout collector for Mac mini

Отдельный видимый браузерный сборщик выплат WB/Ozon. Не использует профили других агентов и не пишет в календарь напрямую: он отправляет снимки в защищённый финансовый API, после чего пользователь проверяет их в панели и отдельно подтверждает перенос.

## Безопасная установка владельцем

1. Скопировать эту папку в `/Users/maxim/marketplace-payout-collector`.
2. Установить свой Playwright: `cd ~/marketplace-payout-collector && PATH=$HOME/opt/node/bin:$PATH npm install`. Именно с `PATH`: node на mini лежит вне системного PATH, и `npm` по полному пути падает с `env: node: No such file or directory`. Браузер не скачивается — сборщик запускает системный Google Chrome. Свой Playwright нужен, чтобы обновление или переезд соседнего `shelf-collector` не роняли сбор выплат.
3. Завести секрет. `FINANCE_MONITOR_SECRET` должен быть задан **и на сервере** (Vercel → Production), **и** в `.env` сборщика — одинаковый. Если на сервере его нет, роут принимает только `CRON_SECRET`, а его из Vercel уже не прочитать. Значение не присылать в переписку.
   Проверка, что сервер видит секрет: `curl -s -X POST -H "Authorization: Bearer <секрет>" -H "Content-Type: application/json" -d '{}' https://<панель>/api/opiu/browser-payout-snapshots` — ответ `Некорректный снимок выплаты` означает, что секрет принят (данные пустые), а `Нет доступа` — что нет.
4. Создать `targets.json` по `targets.example.json`. Для WB добавить отдельную строку на каждый кабинет с точными `cabinetId`, `companyId`, `accountId`, главной страницей и URL раздела выплат.
5. Права: `chmod 700 . && chmod 600 .env targets.json`.
6. Один раз через VNC выполнить `/Users/maxim/opt/node/bin/node collector.mjs --login`, войти в каждый кабинет в открытых вкладках, затем остановить процесс `Ctrl+C`. Профиль останется в `chrome-profile`.
7. Проверить вручную: `/Users/maxim/opt/node/bin/node collector.mjs --collect`, затем `tail -50 logs/collector.log`.
8. Только после успешной проверки скопировать plist в `~/Library/LaunchAgents/` и выполнить `launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/ru.kreonopt.marketplace-payout-collector.plist`.

Сбор запускается раз в 6 часов. При CAPTCHA/блокировке он прекращает обход до следующего запуска. Скриншоты нераспознанных страниц остаются только локально на Mac mini.

## Чего сборщик НЕ делает

- Не пишет в календарь. Снимок — это предложение: он виден в панели прогноза, а строку в календарь создаёт человек кнопкой «Утвердить и перенести».
- Не угадывает. Сумма берётся только рядом с подписью «К перечислению»/«К выплате», дата — только рядом с «Дата выплаты»/«Дата перечисления». Нет подписи и нет однозначного кандидата — строка пропускается с записью в лог, а не заполняется первым попавшимся числом (первым числом в строке обычно стоит выручка, а первой датой — начало периода).
- Не считает «К перечислению» отправленными деньгами: такая строка приходит со статусом «ожидает перевода».

## Что нужно проверить на живой странице при установке

Точные подписи колонок у WB и Ozon видны только в самом кабинете. При первом ручном `--collect` нужно сверить с `logs/collector.log`:

- сколько строк распознано и сколько пропущено (`row_skipped`) — массовый пропуск означает, что подпись на странице другая, и список якорей в `parsePayoutRow.mjs` нужно дополнить;
- совпадают ли сумма и дата у 2–3 строк с тем, что показывает кабинет;
- попал ли в `reportId` номер отчёта, а не случайное слово.

До этой сверки автозапуск (шаг 8) включать не нужно.
