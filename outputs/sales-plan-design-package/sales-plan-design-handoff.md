# Передача дизайнеру: раздел «План продаж»

## Что передаётся

Пакет содержит финальную постановку и рабочий кликабельный референс интерфейса планирования продаж по кабинетам Wildberries. Старые концепты не являются частью постановки.

## С чего начать

1. Прочитать `sales-plan-designer-prompt.md` — это самостоятельный промпт, который можно целиком вставить в дизайн-ИИ или использовать как бриф.
2. Прочитать `sales-plan-per-cabinet-design.md` — полное продуктовое и UX-ТЗ.
3. Открыть `cabinet-sales-plan-design.html` в Chrome — это кликабельный референс логики и плотности страницы.
4. Сверить основные состояния по PNG в папке `screenshots`.
5. Подготовить макеты и прототип по списку обязательных экранов из ТЗ.

## Зафиксированные продуктовые решения

| Вопрос | Решение |
|---|---|
| Область плана | Один кабинет / юрлицо и один месяц |
| Кабинеты | Optima, Retail Family, Galerin, далее список расширяется |
| Главная единица | Цветовая вариация товара |
| Родительский артикул | Только группа и итоги, не строка ввода |
| Размеры | Агрегированы внутри цвета в первой версии |
| Дневной ввод | Заказы, шт. по каждому цвету |
| Цена | Задаётся по цветовой вариации |
| Выкуп | Задаётся в процентах по цветовой вариации |
| Реклама | Процент от заказной выручки до выкупа |
| Утверждение | Блокирует версию; изменения только новой версией |
| РНП | Получает утверждённую версию и показывает план-факт по цвету и дню |
| Новый товар | Можно завести вручную без nmID и позже связать с WB |

## Формула, которую нельзя менять

```text
Рекламный расход за день = Заказы × Цена × Реклама% / 100
```

Пример: 8 заказов × 13 500 ₽ × 12% = 12 960 ₽.

## Что дизайнер может уточнять визуально

- точную ширину закреплённых столбцов;
- использовать popover или правый drawer для редактирования дня;
- плотность строки и высоту заголовка;
- представление истории: drawer или отдельная страница;
- способ сворачивания моделей;
- конкретные цвета нейтральных и статусных состояний в рамках текущего дизайн-языка.

Бизнес-правила кабинета, цвета, формул, утверждения и передачи в РНП менять нельзя без отдельного согласования.

## Чек-лист проверки результата

- [ ] В дизайне нет редактируемого режима «Все кабинеты».
- [ ] Модель `NV-08-35` показана группой, а Graphite, Black и Milk — отдельными строками.
- [ ] Все дни месяца доступны, выходные различимы.
- [ ] Есть режимы «Заказы», «Реклама» и «Заказная выручка».
- [ ] Сумма рекламы совпадает с формулой от заказной выручки.
- [ ] Можно добавить несколько цветов новой модели.
- [ ] Видны ошибки до отправки на согласование.
- [ ] Утверждённая версия полностью read-only.
- [ ] Показаны версии, автор и время утверждения.
- [ ] Есть состояние ошибки и повтора передачи в РНП.
- [ ] РНП показывает план-факт по цвету и дню.
- [ ] Подготовлены desktop, tablet и mobile состояния.

## Ограничение референса

HTML-макет демонстрирует структуру, расчёты и ключевые взаимодействия, но использует тестовые товары. Реальные цвета, внутренние артикулы и nmID должны поступать из данных Wildberries и справочника финансовой панели. Макет не является готовой production-реализацией.
