# Как применить эту миграцию

Нужно один раз выполнить SQL-файл `202609090001_wb_advert_spend_history.sql` в самой базе — мёрдж PR в `main` этого не делает автоматически.

1. Откройте [supabase.com/dashboard](https://supabase.com/dashboard) → проект финансовой панели.
2. В левом меню — **SQL Editor** → **New query**.
3. Откройте файл `supabase/migrations/202609090001_wb_advert_spend_history.sql` в этом репозитории, скопируйте всё содержимое (или возьмите текст из сообщения, которое пришлёт Алина).
4. Вставьте в SQL Editor и нажмите **Run**.
5. Должно появиться сообщение об успехе и создаться таблица `wb_advert_spend_history` — проверить можно в **Table Editor** слева.

После этого ничего вручную запускать не нужно — крон сам подхватит новую таблицу в течение часа (задача `/api/sync/advert-spend-history`, раз в час) и начнёт заполнять её данными «Истории затрат» на рекламу WB (баланс/промо-бонусы) за последние 30 дней.

Если хочется проверить сразу, не дожидаясь крона — откройте в браузере (в той же вкладке, где вы залогинены в панели под ролью «Директор» или «Финансы»):

```
https://finance-panel-two.vercel.app/api/sync/advert-spend-history
```

Ответ `{"ok":true, ...}` с числом строк по каждому кабинету — значит всё сработало. Если ответ покажет ошибку — пришлите её текст Алине, она поправит.

Если что-то пошло не так при выполнении SQL (ошибка в SQL Editor) — ничего в проде не сломается: код в панели рассчитан на то, что таблицы ещё нет, и просто продолжит работать по-старому (строка «ВБ продвижение» — прежняя сумма, «Бонусы» — 0).
