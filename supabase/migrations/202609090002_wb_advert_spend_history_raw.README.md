# Как применить эту миграцию

Маленькая, одна колонка. Нужно один раз выполнить в базе — мёрдж PR в `main` этого не делает автоматически.

1. Открыть [supabase.com/dashboard](https://supabase.com/dashboard) → проект финансовой панели.
2. **SQL Editor → New query**.
3. Вставить и выполнить (**Run**):

```sql
alter table public.wb_advert_spend_history
  add column if not exists raw jsonb;

notify pgrst, 'reload schema';
```

4. Сообщение об успехе — готово, ничего проверять в Table Editor отдельно не нужно (это просто новая колонка в уже существующей таблице).

5. Дальше можно либо подождать час до автопрогона крона, либо ускорить — открыть в браузере (в вкладке, где вы залогинены в панели под ролью «Директор»/«Финансы»):
```
https://finance-panel-two.vercel.app/api/sync/advert-spend-history
```

После этого напишите Алине — она посмотрит, что записалось в новую колонку `raw`, и на основе этого доделает точную привязку рекламных расходов к брендам Norvia/Heaton.

Если миграцию не применить — ничего не сломается, просто колонка `raw` не будет писаться (код это переживёт), и точную привязку по названию кампании нельзя будет доделать, пока миграция не применена.
